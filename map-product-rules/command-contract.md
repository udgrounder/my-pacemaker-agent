# map-product Command Contract

이 표는 source 전용 운영 명령과 profile의 단일 계약표다. Runtime에는 이 명령이나 source 경로를 배포하지 않는다.

| Command | Trigger / Input | Checks and gate | Output / failure | Prohibited |
|---|---|---|---|---|
| `install.py --dry-run` | 빈/없는 명시 대상, agent, 선택적 `--runtime-config-json` | template·spec·hook·Python·project config 및 `runtime.*` additive migration 검사 | project root·Runtime·workspace/issues·docs/INDEX·`.mpa/config/config.yaml` 생성/보강 계획 / 파일 무변경 | 기존 설치 update, 기존 사용자 영역 변경 |
| `project_config.py audit` | 설치 대상의 `.mpa/config/config.yaml` | schema·필수 필드·경로 불일치·민감정보 패턴 | warning-level audit와 semantic checksum / 파일 무변경 | 절대 경로를 중앙 receipt·release asset·issue로 복사 |
| `sync-runtime` | Runtime source 변경 | symlink·비정상 파일 거부 | `dist/.mpa/runtime` 동기화 | `dist/workspace` 변경 |
| `prepare-release` | **사용자 명시 릴리즈 요청** 또는 **배포 요청 시 최신 release 부재**, argv validation과 metadata, 선택적 `--runtime-config-json` | UTC `YYYYMMDDHHMMSS-uuid8` release ID 생성, source/dist 동기화, validation 성공, ZIP·manifest·note·release receipt 상호 참조, `runtime.*` additive migration 검증 | 단일 release ID와 bundle 경로, checksum 증빙 / 생성분 원자 정리 | Runtime 변경·검증만으로 실행, Git clean gate, 사용자 자산·기존 config 값 포함 |
| `release-audit` | active release bundle | bundle 파일 inventory·schema·ZIP·assets·receipt·validation 참조 | audit 결과 / 오류 목록 | legacy artifact를 active로 허용 |
| `history-cleanup` | **사용자가 명시한 이력 정리 요청**, 선택적 `--keep` 및 `--backup-keep` | 기본 dry-run으로 release bundle·등록 대상의 deployment history/receipt·성공 `runtime.zip` backup 후보를 전체 제시. `--apply`에는 실행자·승인자·승인 기록 필수 | 후보 JSON / 승인된 apply 시에만 release·history·receipt·관리형 backup 정리. registry 불일치 대상·실패 backup·사용자 snapshot은 경고·보존 | prepare-release, deploy, rollback 중 자동 정리; dry-run 없이 삭제; 등록되지 않았거나 fingerprint 불일치 대상 삭제 |
| `deployment-dry-run` | manifest, target, target-ref | release package·target fingerprint·release/history·config checksum/migration 검사 후 대상 최상위 `workspace/issues/*.md`에 공통 preflight 실행. receipt에는 policy/normalization version, safe issue ID, raw·normalized checksum, normalized identity, classification/status/reason code, expected destination state만 결박 | 만료 가능한 dry-run receipt와 issue별 `collectable`/`blocked`/`not_candidate`·설정 추가 후보 고지. 하나라도 `blocked`면 실패하고 `not_candidate`는 보존·batch 제외. target 절대경로는 receipt 대신 Git 비추적 로컬 등록부에만 기록 | 대상 변경, issue 원문·credential·machine path의 receipt 노출, 하위 issue 디렉터리·tasks/docs/memory 읽기 |
| `deploy` | recorded dry-run, 실행자·검증자·승인 | target fingerprint·release/asset/history/config/만료와 issue receipt 전체·후보 집합 추가/삭제 재검증; 배포 전 `.mpa/runtime`와 migration 대상 config backup | Runtime 교체·검증과 config migration 후 승인된 `collectable` batch만 commit. collection 또는 이후 backup·receipt 실패 시 issue 이동과 Runtime·MPA config를 함께 rollback. 성공 시 `from_release → to_release`, 수집·원본 정리 결과와 검증된 `runtime.zip` backup 기록 | 기존 user config 값 변경, 승인 issue 원본 외 workspace 변경, docs·agent 설정·일반 소스 변경, 과거 이력 자동 정리 |
| `rollback` | target 또는 등록된 target-ref, version backup, release ID, 실행자·검증자·승인 | target history와 backup 범위 검사, marker·`runtime.zip`·config snapshot 무결성 확인. target 생략 시 로컬 등록부 fingerprint 일치 확인 | Runtime과 MPA config를 함께 rolled_back receipt/history로 복원하고 실행자를 기록 | legacy `runtime/` backup 또는 backup 범위 밖 읽기·복원, 공유 receipt에 target 절대경로 기록 |
| `issue-create` | producer/router가 발견한 개선·지식 | raw credential 검사 → raw metadata/type kind 분류. `methodology_improvement`만 중앙 issue로 작성하고 machine path는 생성 시 placeholder로 표현 | 방법론 issue 생성 또는 기능 보완은 tasks/docs, 아키텍처·계약·역할 함정·도메인 지식은 memory와 두 색인에 같은 작업 단위로 기록 | 비방법론 중앙 issue 생성, credential 자동 정제, 도메인 지식을 issue handoff로 미루기 |
| `issue-collect` | 명시 프로젝트의 단일 issue 또는 승인된 동일 kind update batch | raw credential → raw metadata/type kind → machine path 정규화 → normalized checksum/identity·inbox/archive/destination 충돌 순의 공통 preflight; no-clobber 게시·checksum 확인 후 원본 제거·부재 확인 | `collectable`만 inbox로 이동. `blocked`는 실패, `not_candidate`는 원본 보존·producer로의 asset handoff 안내 | raw credential 자동 정제, dry-run 고지 없는 batch 수집, 덮어쓰기, project `tasks/docs/memory` 자동 수정, 별도 collection receipt |
| `issue-archive` | 사용자 검토 뒤 inbox issue, 결정·근거, 채택 시 task plan | 채택 task plan 존재·archive 충돌 확인 | 이슈 파일에 사용자 결정·근거·연결 작업을 기록한 archive / 실패 시 inbox 보존 | 별도 review·triage receipt, 결정 없는 archive |
