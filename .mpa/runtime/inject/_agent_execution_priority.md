# 에이전트 실행 우선순위

> 독립 비평·구현 검증의 실행 방식과 실패 처리 정본. `layer1_critique.md`, `layer1_review.md` 및 이를 호출하는 워크플로우에서 읽는다.

## 독립 실행의 완료 조건

1. 서브에이전트를 **대화 상속 없이** 호출하고 해당 단계가 지정한 파일·검토 지시만 전달한다. 도구 존재만으로 격리를 보장하지 않는다.
2. 호출 완료와 유효한 산출물을 확인한다. 비평은 `critique.md`, 구현 검증은 단계별 review 파일에 대상·근거·판정이 있어야 한다. 빈 파일·저장 성공 문구만으로 검토 완료로 간주하지 않는다.
3. 사용자 소유 새 작업을 만드는 것으로 대체하지 않는다. 새 작업 생성은 사용자가 요청한 경우에만 한다. 같은 모델의 상관된 오류까지 제거된다는 보장은 없다.

## 실패 처리

도구 없음·격리 불가·호출 실패·산출물 누락은 독립 실행 **미완료**다. 일시 호출 오류나 산출물 누락은 같은 단계에서 **1회까지 재시도**한다. 격리 불가는 재시도하지 않는다. 내부 재시도만으로 사용자 응답을 요구하지 않는다.

| 단계 | 독립 실행 미완료 시 |
|---|---|
| 독립 비평 | 한계·영향을 알리고 **독립 비평 없이 진행할지 사용자에게 확인**한다. 같은 스레드 비평·자가 비평·사용자 소유 새 스레드는 폴백이 아니다. 이미 동일 범위·위험에서 생략 승인을 받았다면 재사용한다. |
| 구현 검증 | 한계를 알리고 **자가 검증**으로 계속한다. 이를 독립 검증이라고 기록하지 않는다. 확인 못 한 항목은 **미확인**으로 남긴다. |

비평 생략이 승인되면 생략 사실과 남은 위험을 기록한 뒤 기존 구현 승인 절차를 따른다. 실제 사용자 결정·권한·위험이 달라질 때만 새 확인이 필요하다.

## 자가 검증의 한계와 증거

자가 검증에서는 기존 대화 맥락을 지울 수 없으므로 독립성을 주장하지 않는다. plan의 기준과 실제 파일·실행 결과를 대조하고, 실패 증거를 찾으며 각 판정에 근거를 남긴다. 확인 불가능한 환경·항목은 이유와 남은 확인을 보고한다. 자가 검증이 실패하거나 새 위험을 발견하면 `layer1_review.md`의 명세·위험 경계에 따라 처리한다.
