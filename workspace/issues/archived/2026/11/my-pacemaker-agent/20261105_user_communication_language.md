# 사용자 소통 언어 기준과 독립 실행 전달 보완
**타입**: 방법론 개선
**발견 상황**: 사용자가 한국어 이외 언어로 소통하는 사례를 보고해 현재 Runtime·에이전트 진입 규칙을 검색했다. 명시적인 사용자 소통 언어 기준을 찾지 못했다. 실제 발생 대화는 제공되지 않아 발생 원인은 미확정이다.
**적용 범위**: 모든 프로젝트

## 현재 방식
규칙 본문은 한국어지만 사용자 응답 언어의 우선순위·적용 범위·예외가 명시되어 있지 않다. 대화 미상속 독립 실행의 전달 계약에도 결과 작성 언어가 없다. 외국어 도구 결과·예시·원문이 사용자 설명 언어를 바꾸지 않도록 하는 기준도 없다.

## 개선 방안
- 항상 로드하는 공통 규칙에 한국어 기본 소통 및 사용자 명시 언어 요청 우선 기준을 둔다. 영어 코드·로그·붙여넣기 자료만으로 소통 언어를 변경하지 않는다.
- 진행 안내·질문·승인 요청·오류 설명·최종 보고를 같은 소통 언어로 작성한다. 코드·식별자·원문 인용은 보존하고 사용자 설명을 소통 언어로 덧붙인다. 명시적으로 외국어 산출물을 요청하면 해당 산출물에 한해 적용한다.
- 대화 미상속 서브에이전트에 소통·결과 작성 언어를 작업 조건으로 전달한다. 구현 대화를 넘기지 않으며 메인은 외국어 결과를 사용자 언어로 요약한다.
- 출력 직전 사용자에게 보이는 설명의 언어를 확인한다. 도구 자체 UI와 원시 로그의 번역까지 보장하지 않는다. 단순 정규식으로 외국어 토큰 전체를 차단하지 않는다.
