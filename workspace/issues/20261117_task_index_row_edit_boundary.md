# INDEX 한 행 삭제의 편집 범위 제한과 보존 확인
**타입**: 방법론 개선
**발견 상황**: 전제 기반 설계 질문 작업의 완료 처리에서 INDEX 한 행을 제거하려고 사용한 정규식이 줄 경계를 넘어 뒤쪽 전체와 Layer 2 마커까지 삭제했다. 후속 전체 정합성 점검에서 발견했다.
**적용 범위**: 모든 프로젝트

## 원인·근거
- Serena replace_content의 regex 모드는 DOTALL·MULTILINE으로 실행된다.
- 행 삭제 패턴에 줄 경계를 제한하지 않은 와일드카드를 사용해 대상 행부터 마지막 개행까지 일치했다.
- 잘못된 편집 뒤 도구 성공과 대상 작업 이름 부재만 확인하여 다른 행·점검 기록 소실을 놓쳤다.

## 이번 복구
실제 active 4개·hold 1개의 plan과 직전 대화에 보존된 INDEX·Git 추적본의 Layer 2 마커를 대조해 5행과 과거 마커 10개를 복구했다. done 이력으로 active 상태를 추정하지 않았다.

## 개선 제안
단일 행은 원문 전체의 literal 치환이나 개행을 제외하는 패턴으로 편집한다. 편집 전후 다른 행 집합·정렬·Layer 2 마커 보존과 실제 active/hold 폴더 일치를 함께 확인한다. 정규식 도구의 실행 플래그를 확인하고 수정 대상이 사라졌다는 사실만으로 성공을 판정하지 않는다.

## 관련 정정 — 공통 규칙 보완 구현 중
상태 기록을 정리하는 과정에서도 파일 끝까지 임시 문구로 교체하는 잘못된 요청이 만들어졌다. 자동 검토가 승인 범위와 증거 삭제 위험을 이유로 차단해 실행되지 않았다. 이후 현재 상태 블록을 읽어 도구 출력에서 원문을 그대로 확보하고, 실제 구현·검증 결과를 담은 literal 치환으로만 갱신했다. 목적에 맞지 않는 임시 문구를 편집 요청에 넣지 않고 변경 전후 상태·증거 보존을 먼저 확인해야 한다.
