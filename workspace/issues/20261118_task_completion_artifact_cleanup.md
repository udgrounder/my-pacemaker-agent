# 작업 완료 시 역할을 마친 검토 자료·판단 근거·스냅샷 정리
**타입**: 방법론 개선
**발견 상황**: 사용자가 완료 후에도 리뷰·평가 문서, 해결된 판단의 중간 근거, 원문 스냅샷이 남는다고 지적했다. 최근 완료 작업 2건에도 검토 문서와 runtime_before.json(각각 76,674바이트·44,346바이트)이 남아 있다.
**적용 범위**: 모든 프로젝트

## 사용자 보완 — 2026-11-18
리뷰·평가에서 발견한 항목은 작업 중 대부분 해결되며 남은 항목도 처리 불필요로 판단될 수 있다. 그때 검토 원본과 해결 과정에서만 필요했던 판단 근거·스냅샷은 역할을 마친다. 완료 후 보관 필요성은 현재에도 유효한 정보와 후속 조치가 있는지를 기준으로 판단한다.

## 현재 방식의 공백
완료 절차는 승인·INDEX 정리·done 이동·연결 확인을 수행하지만, 처리된 검토 결과와 그에 종속된 중간 자료를 정리하는 단계가 명확하지 않다. 최초 제안도 실제 검증에 사용됐다는 이유로 상세·스냅샷 보관을 넓게 전제했다. 과거 사용 여부와 현재 필요성을 구분하도록 보완한다.

## 개선 방향
- 완료 전에 검토·평가의 지적별로 해결됨, 처리 불필요, 여전히 유효한 사항을 확인한다. 처리 불필요로 판단한 항목을 자동으로 후속 TODO로 만들지 않는다.
- 해결됐거나 처리 불필요한 검토·평가 원본은 정리 대상으로 본다. 이 원본을 뒷받침하기 위해 만들었던 판단 메모·추출물·비교 자료·스냅샷도 같은 기준으로 함께 정리한다.
- 현재 유효한 제약·수용한 위험·후속 조치가 있다면 필요한 내용만 기존 plan·changelog·운영 안내 등 알맞은 최종 문서에 반영한다. 파일을 보관하기 위해 내용 전체를 다른 문서에 복제하거나 새 요약 파일을 만들지 않는다.
- 최종 결과를 이해하는 데 필요한 핵심 결정 이유·사용자 승인·검증 결론은 간결하게 남긴다. 처리 과정 전체나 해결된 모든 판단 근거의 영구 보관을 기본값으로 삼지 않는다.
- 자료를 계속 보관하려면 현재의 구체적인 재현·복구·미해결 의존 등 이유가 있어야 한다. “한때 검증에 사용했다”, “나중에 쓸지도 모른다”만으로 남기지 않는다. 필요한 원문을 없앤 뒤 checksum만으로 복원 가능하다고 주장하지 않는다.
- 정리는 해당 작업이 생성한 보조 자료를 대상으로 한다. 사용자 원본·제품 산출물·실제로 진행 중인 승인 복구 자료와 다른 작업의 자산은 별도로 판단한다.
- 삭제 대상의 참조·승인 무결성을 함께 정리하고 남길 정보와 실제 파일 상태를 확인한다. 정리 여부는 기존 작업 기록에 필요한 만큼만 남긴다.

## 적용 상태
사용자 보완과 독립 비평을 반영한 [MPA 적용 계획서](../tasks/done/20261118_completion_artifact_cleanup/plan.md)를 작성했다. 독립 설계 비평 후 사용자가 계획 구현을 승인했다. Runtime 상세 절차·소비 지침·템플릿·설명/메모리와 배포용 사본을 반영했으며 전체 253건 테스트를 통과했다. 독립 1차/2차 검증도 수정 필수 결함 없이 마쳤다. 2026-11-23 사용자 완료 승인 후 이번 작업의 역할 종료 검토 원본 4개를 정리하고 계획서·최종 결론/한계를 보존해 done 이동했다. 이전 완료 작업의 파일 정리/삭제는 수행하지 않았다.
