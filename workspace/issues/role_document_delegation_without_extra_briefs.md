# 역할 문서 기반 위임에 별도 작업지시서를 과도하게 추가한 해석 정정

**타입**: 방법론 개선
**발견 상황**: 역할별 작업 문서 도입 계획을 설명하면서 독립 작업마다 별도 work 문서를 추가했다. 사용자는 문서 타입에 따라 필요할 때 독립 서브에이전트로 실행하는 뜻이라고 정정했다.
**적용 범위**: 모든 프로젝트

## 현재 방식

역할별 내용을 분리해 담당에게 전달하려는 요청을 별도 위임용 작업지시서 생성 요구로 확대 해석하면 역할 문서와 지시서의 내용이 중복되고 관리 부담이 커진다.

## 개선 방안

역할 문서 자체를 실행 입력으로 사용한다. 문서 타입·실제 독립성·분리 이익을 판단해 메인 또는 서브에이전트가 담당한다. 필요한 호출 범위는 해당 문서의 섹션과 호출 지시로 지정하고 추가 파일을 자동 생성하지 않는다. task_role_documents 계획에서 별도 작업지시서 구조를 제거했으며 Runtime은 미구현이다.

## 후속 확정

별도 작업 문서/폴더를 금지하는 뜻은 아니다. 기본은 역할 문서 직접 사용이며, 작업이 크거나 독립 조사·자료·산출물을 분리 관리할 이익이 있으면 필요한 문서와 하위 폴더를 생성한다. 상위 plan과 범위·담당·의존성·결과를 연결하고 승인/실행 권한을 자동 확대하지 않는다.
