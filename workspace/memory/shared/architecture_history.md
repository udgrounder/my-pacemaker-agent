# 아키텍처 변경 이력

현재 유효한 설계는 [architecture.md](architecture.md)를 기준으로 한다. 이 파일은 변경 경위·이전 표현·대체된 판단을 보존하며 현재 설계의 정본으로 사용하지 않는다.

## 2026-11-04 — 현재 설계와 이력 분리

- 사용자 요청: architecture.md는 최종 설계만 유지하고 변경 이력을 별도 파일로 분리한다.
- 변경: 현재 문서 상단에는 이 파일의 안내 링크만 두고, 본문은 주제별 현재 설계로 유지한다. 뒤에 추가돼 있던 선택형 작업 문서 계약은 핵심 설계 결정으로 통합한다.
- 보존 범위: 기존 문서에 남아 있던 아래 원문과 설계 출처를 이관했다. 기존 문서는 날짜별 타임라인이 아니었으므로 과거 결정 날짜는 추정하지 않는다. 현재 유효한 호환 동작과 제약은 architecture.md에 유지한다.

### 이전 문서 관리 원칙

> ### shared/ 파일은 로그가 아니라 현재 상태 스냅샷
> 결정이 바뀌면 기존 항목을 교체한다. 이전 내용을 남기지 않는다.
> 폐기된 규칙은 삭제한다.
> append 누적은 모순을 만든다.

현재 원칙은 변경 경위를 이 파일에 먼저 보존한 뒤 architecture.md의 해당 주제를 교체하는 것이다. 이전 표현의 “이전 내용을 남기지 않는다”는 현재 설계 문서에 한정하며 이력 삭제를 뜻하지 않는다.

### 계획·승인 형식 전환 관련 이전 서술

> changelog는 계획·결정 변경과 실제 구현 결과를 구분하는 이력 정본이다. 새 reqspec-v1 plan의 승인 갱신은 changelog에 기록하고 기존 plan 내부 표는 배치 호환을 유지한다. 접두사 없는 legacy 해시는 기존 재승인 절차를 따른다.

> 새 major·minor plan은 `승인해시`의 `reqspec-v1:<16자리 소문자 16진수>` 접두사와 프론트매터 `승인대상: 요구사항 명세`, `## 요구사항 명세` 블록의 조합으로 식별한다.

현재 문서는 현행 형식과 지원하는 기존 형식의 동작을 직접 설명한다. 기존 plan 내부 표·접두사 없는 해시의 호환 및 재승인 조건은 계속 유효하다.

### 통합 전 선택형 작업 문서 계약

> ## 선택형 작업 문서의 현재 계약
>
> plan은 최소 요구사항·승인·전체 상태 정본이다. major/minor는 문서 수를 강제하지 않는다. implementation(설계/실행/진행), verification(검증 방법), ui_design(화면 기준)은 분리 이익이 있는 경우만 선택한다. inject/task_documents.md는 선택·인계·전환의 정본, hooks/task_documents.py는 읽기 전용 구성/경로/기준 검사 및 역할 입력의 소유자다. plan_hash의 승인/복구 거래는 유지하고 audit/approve/check·gate·SessionStart는 문서 연결 문제를 승인 복구와 구분한다. 큰 작업/조사의 하위 자료는 상위 plan에 연결하며 단일 수정자 원칙과 별개다.

이 계약은 의미를 바꾸지 않고 architecture.md의 “핵심 설계 결정”에 통합했다.
