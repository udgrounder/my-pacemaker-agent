## 요구사항 명세

### 요청 기준

감사 결과를 바탕으로, agent가 사용자의 의도에 맞게 자율적으로 작업하되 의도·가치·완료 판단이 필요한 지점에서만 사용자 통제를 받도록 규칙과 설명을 정렬한다.

### 목적

minor 작업에서 계획 범위 안의 가역적 실행은 자동으로 진행하고, 결과의 완료 판단만 사용자(또는 위임자)가 확인한다는 현행 실행 계약을 모든 규칙·설명에 일치시킨다. 또한 현업의 work item 계층에 맞춰 요청·작업 항목·실행 항목을 구분하고, 기존 태스크는 호환 경계의 별칭으로만 남긴다.

### 범위·제외 범위

- 범위: minor 완료 승인 설명의 정합성, guidebook 완료 흐름, glossary와 주요 사용자 대면 안내의 `요청`/`작업 항목`/`실행 항목` 정의.
- 범위: `.mpa-workspace/` 수정 후 release 절차로 `dist/.mpa-workspace/` 동기화와 새 immutable release bundle 생성.
- 제외 범위: completion hook의 상태 검증 로직 변경, 승인 단계를 추가하는 변경, OpenAgent 통합, 파일 경로·프론트매터·hook 식별자의 호환성 파괴 변경.

### 완료 기준

- 실행 규칙·session protocol·architecture·guidebook이 minor의 “계획 승인 자동 / 완료 확인은 사용자 확인”을 같은 의미로 설명한다.
- guidebook의 완료 흐름에 사용자 완료 확인이 명시된다.
- glossary와 주요 안내가 요청(사용자 의도), 작업 항목(계획·상태·증빙 관리 단위), 실행 항목(작업 항목 안의 세부 단계)을 구분한다.
- 기존 `tasks/` 경로와 `태스크` 프론트매터는 호환성을 위해 유지하며, 사용자 대면·개념 설명에서는 작업 항목을 기본 용어로 쓴다.
- source와 dist가 release 도구로 동기화되고, 테스트와 release audit이 통과한 새 release bundle이 생성된다.

### 사용자 결정

- 사용자 확인은 의도·가치·완료 판단에만 두며, 계획 범위 안의 가역적 실행·조사·기록은 agent가 자율 진행한다.
- minor 완료 확인은 자동화하지 않는다. 이는 결과가 사용자 의도에 맞는지 확인하는 유일한 완료 통제다.

### 변경 불가 제약

- `dist/.mpa-workspace/`를 직접 편집하지 않고 `prepare-release`로만 동기화한다.
- 기존 plan·완료 이력·사용자 설정을 자동 변환하지 않는다.
- release bundle에는 source 전용 map-product 자산·workspace·docs·agent spec을 포함하지 않는다.

### 에이전트 가정

| 가정 | 근거 | 틀렸다면 |
|---|---|---|
| 완료 상태 hook은 이미 사용자 확인 뒤 `완료 승인`만 허용한다 | 감사 결과의 `agent_rules.md`·`code_gate.py` 대조 | hook 계약까지 포함한 별도 수정 범위로 확장한다 |
| README의 minor 완료 설명은 현행 계약과 일치한다 | 감사 결과에서 README는 사용자 확인을 명시 | 추가 수정 대상으로 포함한다 |
