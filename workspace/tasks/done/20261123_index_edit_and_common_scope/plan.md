# 작업 계획서: 작업 INDEX 편집 안전성과 공통 방법론 범위 점검

## 요구사항 명세

### 요청 기준

사용자 요청 “부분 반영된 INDEX 편집 안전성과 공통 범위·프로젝트 사례 분리 이슈 2건을 MPA에 반영할 계획서 작성해줘.”

출처는 INDEX 편집 안전성과 공통 범위·출처 사례 분리 이슈다. 완료된 두 이슈의 처리 근거는 [변경 이력](changelog.md)에 남긴다.

### 목적

작업 INDEX 편집에서 무관한 행이나 점검 기록이 함께 바뀌는 오류를 발견하고 후속 처리를 막는다. 공통 방법론 계획에서는 어떤 프로젝트에서 문제가 발견됐는지와 모든 적용 대상에 실제로 필요한 조건을 구분한다.

### 범위·제외 범위

- `workspace/tasks/INDEX.md`를 생성·등록·갱신·정렬·복구·완료 처리하거나 Layer 2 완료 마커를 기록하는 기존 Runtime 경로에 편집 안전 기준을 연결한다.
- 공통 방법론을 작성·검토하는 기존 경로에서 적용 범위·제외 범위·가정·완료 기준·검증 사례를 확인한다. 특정 프로젝트에서만 유효한 사실은 출처와 근거로 기록한다.
- 범위 밖에는 개별 프로젝트의 업무 정책·데이터 모델·제품 변경, 이미 완료된 계획의 소급 재작성, docs/memory 색인 편집 정책, 새 편집 엔진·hook·승인 단계, 이슈 삭제·릴리즈·설치 대상 배포가 포함된다.

### 완료 기준

- **I1.** 편집 직전에 최신 INDEX에서 해당 작업의 경로·상태·행 원문과 작업 폴더를 확인한다. 의도한 최종 내용만 대상 행에 반영한다. 정확한 literal 편집을 우선 사용하며 정규식이 필요하면 개행을 넘지 않게 제한하고 일치 건수를 확인한다. 전체 원문은 변경 범위와 보존 여부를 확인하는 기준으로 사용한다.
- **I2.** 일반 작업에서는 이번에 등록·갱신·이동하는 작업의 행과 실제 plan/폴더 위치만 대조한다. 다른 작업의 누락·중복·경로 불일치는 현재 행을 처리하는 선행 조건이 아니며 다른 행을 추가·삭제·수정·재정렬하지 않는다. 저장 후에는 해당 행에 예상 변경이 반영됐는지와 편집으로 다른 행·표 구조·기존 마커를 건드리지 않았는지 확인한다. 작업 식별과 구현 승인 유효성은 별도로 판단하고 승인된 완료 이동의 일시 차이는 해당 작업에서만 허용한다. 전체 행 정합성 보완은 사용자가 명시적으로 요청한 범위에서만 수행한다. Layer 2 마커 기록은 실제 점검 완료 조건에 따라 별도로 처리한다.
- **I3.** 해당 행이 모호하거나 확인한 뒤 변경됐거나 예상보다 넓은 변경이 생기면 그 작업의 편집·이동을 보류하고 최신 상태를 확인한다. 다른 작업만 동시에 바뀌었다면 그 변경을 보존한 채 최신 INDEX에서 해당 행만 다시 편집한다. 원본과 이번 변경 범위가 확실할 때에만 영향을 받은 부분을 복구한다. 전체 이전본 덮어쓰기나 done 이력으로 추정 복구하지 않는다.
- **S1.** 개선의 재사용 범위로 공통 계획 여부를 판단한다. 범위·제외 범위·가정·완료 기준 및 선택 설계·검증 문서의 기준을 역할·행동·관찰 가능한 판단으로 작성한다. 원천 사례는 출처나 근거로 남기되 위치·라벨·직간접 참조와 무관하게 특정 사례가 공통 합격 여부를 좌우하면 일반화하거나 적용 범위를 다시 확인한다.
- **S2.** 공통 계획 작성과 승인 전 자기 점검, 기존 조건에 따라 수행하는 독립 비평에서 본문과 선택 문서의 기준을 함께 확인한다. minor 직접 작성과 자동 승인 전에도 경량 점검이 도달해야 한다. 실제로 필요한 전제·반례는 일반 조건으로 표현하며 프로젝트 전용 계약과 기존 명세 변경 승인 기준을 유지한다.
- **V1.** source/dist의 실제 로드·소비 경로와 경계 사례를 회귀 검증한다. 기존 승인·완료 처리·Layer 2 발동 조건과 공통 core 크기 기준을 유지한다.

### 사용자 결정

두 이슈의 남은 공통 보완을 한 계획으로 작성한다. 이번 요청은 계획 작성이다. 공동 작업 중 다른 작업의 INDEX 행은 현재 작업의 정합성 판정이나 수정 대상에 포함하지 않는다. 다른 행에 대한 정합성 정리는 사용자 명시 요청 범위에서 수행한다.

### 변경 불가 제약

기존 승인 명세·생명주기 상태·완료 승인 후 이동 순서, 다른 작업 행과 과거 마커를 보존한다. 파생 작업 등록은 최소 plan 저장을 INDEX 첫 편집 앞으로 옮긴다. 안전 조치는 기존 읽기·편집 도구로 수행한다. Runtime 배포용 사본은 기존 sync-runtime 경로로만 갱신한다.

### 에이전트 가정

- 두 보완은 수정 위치와 검증이 달라 각각 추적할 수 있으며, 하나의 승인과 Runtime 동기화로 검토할 수 있다.
- 계획된 지침 변경은 가역적이다. 체크섬이나 검사 결과만으로 동시 쓰기 방지 또는 모델의 실제 준수를 주장할 수 없다.
- 최종 편집 경로는 구현 직전 소스 전체에서 확인한다. 문서를 읽거나 출력만 안내하는 경로와 실제 쓰기 경로를 구분한다.

## 설계 기준

### 사전 조사

- INDEX 편집의 줄 경계와 보존 대조는 `core/agent_rules_detail.md`의 Layer 2 완료 마커 경로에 있다. 공통 core 유지보수와 완료 경로는 상태·정렬·마커 보존을 요구하지만 다른 편집 경로까지 동일한 편집 안전 기준을 연결하지 않는다.
- 공통 범위·출처 사례 분리는 과거 개별 계획에서 정정했다. 현재 `layer1_design.md`의 전제 확인과 `layer1_critique.md`의 자기 점검·독립 비평에는 같은 점검이 명시돼 있지 않다.

### 적용 위치

세션 시작과 일반 작업 종료 때 전체 정렬·정리를 수행하도록 읽히는 기존 core 문구도 좁힌다. 다른 작업의 불일치가 보여도 현재 작업은 해당 행 기준으로 처리한다. 사용자가 전체 정합성 점검을 요청하면 전체 대조를 수행하고, 수정은 요청된 범위에서 처리한다.

| 보완 | 정본과 연결 경로 |
|---|---|
| INDEX 편집 | `core/agent_rules_detail.md`에 상세 기준을 두고 기존 Runtime 쓰기 **전**에 정본을 읽도록 연결한다. 세션 시작 유지보수, Layer 0의 신규·기존 프로젝트 작성, major/minor 등록, 발견의 파생 등록, active/hold·행 정보 갱신, 완료 행 제거, Layer 2 복구·마커 기록을 각각 추적한다. 기존 참조가 저장 뒤에만 실행되는 경로는 순서를 보완한다. `session_start.py`의 안내 출력은 INDEX 쓰기와 구별한다. |
| 공통 범위 | major 설계, minor 직접 작성, 선택 문서 내용 대조, 자기 점검·독립 비평이 함께 참조할 짧은 정본을 상세 규칙에 둔다. minor는 `layer1_design.md` 전체 로드 없이 기존 템플릿·경량 승인 경로에서 적용한다. 선택 문서는 승인 전 실제 설계·검증 기준까지 확인한다. |
| 검증·설명 | 기존 `tests/test_task_index_policy.py`, `tests/test_structure_loading.py` 등 직접 관련 검사에 실제 경로와 누락 사례를 추가한다. 설명이 필요한 공통 로딩·편집 경로는 `docs/mpa-internal-structure.md`에 반영한다. |

### 반례와 처리

- 파생 등록은 기존 발견 출처를 포함한 최소 미승인 plan을 active 폴더에 먼저 저장한 뒤 INDEX 행을 쓴다. 정식 설계는 그 plan을 이어서 보완한다. 행·출처·plan이 최종 대조되기 전에는 파생 등록을 근거로 원래 작업을 종료하지 않는다.
- Layer 0의 후보·의존성·우선순위는 기존 설계 산출물이나 인계에서 추적할 수 있게 보존한다. 새 작업은 최소 plan을 저장한 뒤 활성 INDEX에 등록한다. Layer 0 양쪽 작성 지시·완료 기준·첫 설계 연결을 함께 정리한다. 설치 골격 복사는 임시 설치로 확인하며 설치 코드·배포 골격의 변경은 제외한다.
- 동명 작업 행 또는 중복 등록은 이름만으로 편집하지 않는다. 경로·상태·기대 행을 확인하며 판단이 모호하면 보류한다.
- 현재 작업 행의 위치를 조정해야 하면 다른 행의 상대 순서를 유지한다. 다른 작업 행의 불일치 자체로 현재 작업이 막히지 않는다. 전체 정렬·복구는 사용자가 명시적으로 요청한 범위에서 수행한다. 마커 추가 시에는 기존 중복 방지와 실제 점검 완료 조건을 유지한다.
- 완료 이동을 재개할 때 승인 기록과 원본·목적지·해당 행을 함께 확인한다. 원본만 있으면 승인과 현재 경로를 확인해 해당 행 정리 후 이동하며, 행이 재등록됐어도 같은 기준을 적용한다. 목적지만 있으면 이동을 반복하지 않고 남은 행과 최종 연결을 확인한다. 양쪽 모두 있거나 둘 다 없거나 승인 근거가 불명확하면 보류한다. 이동 실패 시 후속 변경을 덮어쓰지 않는 범위에서만 행을 복구한다.
- 출처에 프로젝트 이름이 있어도 근거로 명시하면 허용한다. 익명화한 예시라도 특정 업무 처리 방식이 공통 완료 조건이면 검토한다. 여러 프로젝트가 공유하는 실제 제약은 적용 조건과 근거를 명시해 유지한다.

## 실행 계획

1. 읽기 조사로 실제 쓰기와 계획 검토 경로를 확정한다. 사용자 구현 승인 뒤 정상 `approve`로 유효한 `reqspec-v1:`을 기록·확인한 후 source 편집에 들어간다.
2. INDEX 상세 기준을 정본에 두고 소비 경로를 연결한다. 다음으로 공통 방법론 작성과 검토의 두 진입점에 범위 점검을 연결한다. 변경은 순차 적용한다.
3. source 변경과 집중 검사를 마친 뒤 `sync-runtime`을 실행한다. 최종 source/dist 동일성, 임시 설치, 전체 회귀, 공통 core 크기, 승인·완료·Layer 2 경계를 차례로 확인한다.
4. major의 독립 구현 검증 1·2차를 진행하고 필수 지적을 해결한 뒤 결과와 한계를 보고한다. 사용자 완료 확인을 받아 작업을 종료한다.

## 검증 기준

| 사례 | 확인할 결과 |
|---|---|
| 행 등록·갱신·삭제, 실제 완료 마커 추가 | 예상 변경만 발생하고 다른 행·마커 원문과 순서가 유지됨 |
| 유사 이름, 다중 일치, 개행을 삼킨 편집, 이동 실패·중단 | 모호한 편집/이동을 보류하고 실제 상태를 근거로 복구 또는 보고함 |
| 해당 행과 작업 위치 대조 | 다른 행의 누락·경로 불일치·동시 추가가 있어도 현재 작업 행만 정확히 처리함. 해당 행이 중복·동시 변경된 경우는 보류하고 확인함 |
| 공통 계획의 긍정·부정 사례 | 프로젝트 명칭은 출처에 허용하되 숨은 업무 전제가 범위·가정·검증에 섞인 경우 발견함. 프로젝트 전용 계획의 고유 계약은 보존함 |
| 정본 참조 삭제·오연결·저장 뒤로 이동 | 주요 등록·복구·완료 경로의 첫 쓰기 전 연결 누락을 검출함 |
| 초안과 파생 등록 | Layer 0 후보 맥락이 보존되고, 최소 plan 저장 → 출처 포함 행 등록 → 대조 → 원래 작업 종료 순서를 지킴. 미승인·구형·복구 대상은 숨기지 않으며, plan 누락·읽기 실패로 모호한 행은 보존·보류함 |
| INDEX 전후 예시 | 임시 문구, 헤더·구분선·설명·빈 줄 소실, 다른 행·마커 변경을 검출함. 현재 작업 행만 옮기는 경우와 정상 마커 추가를 확인함 |
| 완료 이동 재개 | 원본만·목적지만·양쪽·둘 다 없음, 행 재등록 및 승인 근거 부재를 각각 판정함 |
| 승인 전 범위 점검 | major·minor와 선택 문서 진입점을 확인함. 계획 전용 minor 요청은 approve가 실행되지 않고 독립 비평 발동 조건이 유지됨. 선택 검증 문서에만 강제된 출처 사례를 검출하고 정당한 공통 전제와 프로젝트 전용 계약은 허용함 |

임시 데이터와 기존 검사로 확인하고 실제 작업 INDEX를 손상시키지 않는다. 기존 전체 테스트, Runtime 계약 검사, source/dist 파일 동일성, `git diff --check`, 공통 core 34,731바이트 미만을 확인한다. 정적 검사와 사례 대조가 실제 호스트의 편집 안전성과 모델 준수를 강제한다고 보고하지 않는다.

## 검증 결과

계획 단계 자기 점검에서 두 이슈의 기존 반영분·잔여 범위, 공통 조건과 출처 사례의 분리, 정상·실패·전이 사례, 기존 승인과 Layer 2 조건 보존을 대조했다. 설계 독립 비평 기준은 미충족이다. 위험한 데이터 변경이나 외부 영향이 없고, 기존 절차 안의 가역적 문서·검사 변경으로 사용자 가치 결정·다른 도메인의 계약 변경·복잡한 다단계 구현이 없다. major 구현 후의 독립 1·2차 검증은 유지한다.

사용자 요청으로 대화를 상속하지 않는 독립 설계 비평을 수행했다. [비평 원문](critique.md)은 파생 등록·Layer 0 초안, 편집 전후의 보호 영역, 완료 이동 재개, 선택 문서의 간접 업무 제약, 승인 전 minor 경로, 검사와 동기화 순서에서 보완을 요구했다. 해당 조건을 완료 기준·적용 위치·반례·검증에 반영했다. 현재 INDEX는 이 계획 행 1개를 제외하면 기준본과 같으며 마커 11개를 보존했다. 기존 INDEX 정책·구조 검사 21건 통과는 현행 기준선이다.

구현 검증에서 전체 테스트 255건, source/dist 일치, 양쪽 Runtime 계약, 승인해시 및 문서 검사, core 33,381바이트와 diff 검사를 확인했다. 독립 1차의 완료 재개와 승인 직전 대조 누락을 수정했고, 2차는 즉시 수정 필요 0건으로 판정했다. 검사 증거는 정적 회귀와 임시 데이터의 사례 판정이며 실제 모델의 지침 준수나 동시 쓰기 보장을 입증하지 않는다.

## 운영 시 안내 사항

구현 후에는 작업 INDEX 편집과 공통 계획 작성 시 각 기존 진입점에서 새 기준을 적용한다. 완료 전 이슈 처리 여부는 변경 내용과 검증 결과를 대조해 판단한다.

## 현재 상태

사용자 완료 승인에 따라 해당 INDEX 행만 제거하고 완료 경로로 이동했다. 다른 행과 Layer 2 마커 11개를 보존했다. Runtime과 배포용 사본의 반영, 전체 테스트 255건 및 독립 1·2차 검증을 확인했다. 설계 비평과 독립 검토 원본은 완료 보고에서 삭제 범위가 고지되지 않아 보존했다.
