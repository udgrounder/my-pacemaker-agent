## 구현과 검증

### 완료 이슈의 처리 기록

- `20261117_task_index_row_edit_boundary.md`는 INDEX 한 행의 편집이 다른 행과 마커를 함께 지운 사례에서 나왔다. 현재 작업 행만 편집·대조하고 전체 정리는 명시 요청 범위에 한정하도록 반영했다.
- `20261117_separate_source_examples_from_common_scope.md`는 출처 프로젝트의 사례가 공통 적용 범위와 합격 조건에 섞인 문제를 다뤘다. 계획 작성·자기 점검·독립 비평과 선택 문서에 같은 구분을 적용했다.
- 두 이슈의 Runtime 반영과 독립 검증을 마쳤으며 사용자 완료 승인을 받았다.

- 사용자 완료 승인 “이번 INDEX 편집 안전성과 공통 범위 점검 작업 완료 처리해줘.”를 기록했다. 기존 승인 명세와 독립 검토 결론을 보존한다. 작업 폴더 충돌과 승인 복구 잔존 여부를 확인했다.

- 세션 시작 INDEX 조회에서 저장을 제거했다. 일반 편집, 파생 등록, 완료·재개의 범위를 현재 작업 행에 한정하고, Layer 2 전체 대조·정리의 명시 요청 경계를 명문화했다.
- Layer 0 후보는 설계 인계에 보존하고, 새 파생 작업은 최소 plan 저장 뒤 등록한다. minor와 완료 경로의 기존 승인 조건을 유지한다.
- 공통 범위 점검을 major·minor, 자기 점검·독립 비평, 선택 문서 승인 전 연결에 적용했다. 사례가 다른 문서에서 간접 참조되더라도 실제 합격 조건이면 점검한다.
- 사례 대조: 다른 작업의 누락·경로 차이는 현재 행의 완료를 막지 않는다. 최신 상태에서 별개 행의 변경을 보존하고, 대상 행 충돌은 보류한다. 출처 표시만 있는 사례는 허용하며 선택 검증 문서의 필수 업무 사례는 일반화하거나 범위를 재검토한다. 본 대조는 정책·사례 검증이며 동시 쓰기나 모델 행동의 실행 시험이 아니다.
- 테스트는 source/dist 정책 참조, 저장 전 로드와 누락·늦은 로드 변형, 기존 전체 검사 및 임시 설치를 포함한다.
- 1차 독립 검토 중 전체 대조만 요청된 경우와 실제 정리 요청을 구분하는 경계를 Layer 2의 실행 지시에도 명시했다. 해당 문구와 안전 기준이 실제 사용 절에 있는지 회귀 검사에 추가했다.

### 경계 사례 판정

1차 검토가 지적한 재개·승인 연결을 보완했다. 사용자나 현재 선택 기록이 식별한 중단 작업은 done 목적지만 남아도 해당 경로를 확인한다. 마지막 점검 후 공통 plan 또는 선택 설계·검증 기준이 달라졌으면 승인 직전에 변경된 기준을 대조한다. 관련 규칙의 회귀 검사와 아래 사례 대조를 추가했다.

| 입력 상황 | 지침을 대조한 결과 |
|---|---|
| 다른 작업 행의 누락·잘못된 링크와 정상인 현재 작업 행 | 현재 행만 처리한다. 다른 행의 불일치 자체로 완료를 막지 않는다. |
| 확인 뒤 다른 작업 행만 추가되거나 현재 작업 행도 바뀜 | 전자는 최신 원문에 추가 행을 보존하고 현재 행만 편집한다. 후자는 재확인까지 해당 편집을 보류한다. |
| 대상 행 외에 헤더·설명·과거 마커가 사라짐 | 보존 대조 실패로 이동을 보류한다. 후속 편집의 유실 없이 이번 변경만 복구할 수 있을 때 복구한다. |
| 완료 이동 중단 후 원본만 있거나 목적지만 있음 | 승인과 위치를 대조해 각각 해당 행을 정리하고 이동하거나, 이동 없이 남은 해당 행만 정리한다. 양쪽 존재·부재 또는 승인 불명은 보류한다. |
| 선택 검증 문서에 원천 업무 방식이 유일한 합격 조건으로 포함됨 | 본문이 일반적인 표현이어도 범위 점검에서 걸러 일반화하거나 적용 범위를 다시 확인한다. |
| 같은 사례가 출처에만 있고 합격 판정은 다른 프로젝트에도 적용 가능함 | 출처를 보존한다. 프로젝트 전용 계획에 실제로 필요한 업무 계약도 유지한다. |
