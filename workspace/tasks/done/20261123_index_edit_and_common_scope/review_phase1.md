# 1차 구현 검증

- 대상 작업은 `index_edit_and_common_scope`이며, `task_documents.py inputs --stage review1`이 제공한 `I1–I3`, `S1–S2`, `V1`과 설계·검증 기준을 사용했다.
- 실제 Runtime과 두 회귀 테스트 및 내부 구조 문서를 대조했다. 계획의 실행 기록·changelog·비평 산출물·전체 diff는 참조 범위에서 제외했다.
- 초기 판정은 수정 필요다. 완료 재개와 공통 승인 직전 조건에 각각 누락이 있고, 승인된 검증 사례 중 일부를 확인할 수 있는 회귀 검증이 없었다.

## 검토 결과

### ✅ 정합성 확인

- **정상 경로, 파생 등록 및 현재 행 편집.** `.mpa/runtime/inject/layer1_discovery.md:80–98`은 출처가 담긴 최소 plan 저장 → 상세 기준 로드 → 신규 행 등록 및 행·출처·plan 대조 → 원래 작업의 완료 확인 순서를 둔다. `core/agent_rules_detail.md:151–158`은 현재 행만 식별하고 다른 행의 순서·표 구조·과거 마커를 대조한다. 대상 행이 변했으면 후속 이동을 보류하고 다른 행만 변했으면 최신 원문에 그 변경을 보존한다. 일반 작업에서 무관한 행의 누락과 경로 불일치는 진행 조건이 아니다.
- **최초 설계와 경량 경로.** `inject/layer0_init.md:63–70,125–145,177–181`은 후보·의존성·우선순위를 인계에 보존하고 첫 설계에서 최소 plan을 등록보다 먼저 저장한다. `core/agent_rules_detail.md:428–445`는 minor 직접 작성·자기 점검·자동 승인 전 공통 범위 점검과 계획 전용 분기를 둔다. `inject/layer1_critique.md:3–5,19–25,47–57`과 `inject/task_documents.md:30–39`는 선택 설계·검증 기준에 직접 또는 간접으로 들어간 출처 의존을 검토하도록 연결한다. 정당한 공통 전제와 프로젝트 전용 계약의 보존은 `core/agent_rules_detail.md:160–164`에 있다.
- **기존 점검 발동 및 아키텍처 경계.** `core/agent_rules_detail.md:181–194`은 주기 제안과 실제 완료 마커를 구별하며 같은 날 마커 중복과 과거 마커 변경을 피한다. `inject/layer2_checkpoint.md:75–88`은 전체 대조와 수정 범위를 사용자 요청에 묶는다. 이번 규칙은 기존 편집 도구와 상태·승인 절차를 사용하며 새 hook이나 편집 엔진을 요구하지 않는다.
- **실행 증빙.** `PYTHONPATH=tests python3 -B -m unittest test_task_index_policy test_structure_loading` 22개 통과. 이 실행에는 임시 설치의 INDEX 골격, source/dist 파일 동일성 검사와 core 크기 상한이 포함된다. core는 33,381바이트였다. source/dist Runtime 참조 계약 검사와 대상 파일의 `git diff --check`도 통과했다. 호스트의 실제 쓰기 직렬화나 모델 준수는 이 검사 결과에서 추론하지 않았다.

### ⚠️ 주의 필요

- **[I2·I3] 완료 재개의 진입점이 목적지만 남은 작업을 놓친다.** 정상 완료 중 INDEX 행을 제거하고 폴더를 `done/`으로 옮긴 직후, 최종 경로·행 대조 전에 세션이 끊기면 원본과 행이 모두 없다. 상세 완료 절차에는 목적지만 있는 분기가 있지만, 일반 `태스크 재개`는 `active/`와 INDEX로만 후보를 고르고 후보가 없으면 새 작업 안내로 끝난다. 사용자가 중단된 작업을 구체적으로 지목해도 목적지를 확인하는 연결이 없다. 지목된 작업이나 현재 선택 기록의 정확한 경로만 확인해 상세 완료 분기로 연결하고, 완료 이력 전체 스캔은 피할 수 있다. 근거는 `core/agent_rules_detail.md:173–174,198–225` 및 `hooks/session_start.py:94–115,134–169`이다.
- **[S2] major에서 자기 점검 이후 바뀐 기준을 승인 직전에 다시 확인하는 연결이 없다.** 설계 완료 전에 자기 점검과 필요한 독립 비평을 수행한다. 이후 사용자 검토에서 가정·완료 기준이나 선택 설계·검증의 기준을 갱신할 수 있는데, 구현 승인 직전 분기는 변경 반영 뒤 승인 기록 처리로 바로 진행한다. 공통 계획의 선택 검증 문서가 이때 특정 프로젝트 방식만 합격으로 바뀌면 앞선 검토를 재사용할 수 없다. 마지막 사용자 결정과 문서 변경을 반영한 뒤 변경된 기준에만 공통 점검을 다시 적용하는 연결이 필요하다. 기존 독립 비평 발동 기준과 명세 변경 승인은 유지한다. 근거는 `inject/layer1_design.md:154–196`, `inject/task_documents.md:33–36`이다.
- **[V1] 합의된 경계 사례를 검증하는 회귀 사례가 부족하다.** `tests/test_task_index_policy.py:42–76`은 일부 경로의 지침 순서와 새 설치 골격을 확인한다. `tests/test_structure_loading.py:59–68,209–290`은 참조 삭제·오연결과 일부 지침 문자열을 확인한다. 이 검사에서는 다른 행만 동시에 바뀐 INDEX와 표 구조·마커를 훼손한 INDEX의 전후 대조, 파생 plan 저장·등록·대조·원래 작업 종료 순서, 완료 재개의 원본/목적지 조합·승인 누락·행 재등록, 선택 검증 문서에만 강제된 출처 사례 및 정당한 공통 전제를 각각 판정하는 자료를 확인할 수 없다. 승인된 사례를 임시 문서나 표로 실행해 기대 결과와 대조하고, 실제 경로가 바뀌었을 때 검사가 실패하는지 확인해야 한다.

#### 지침을 따라 대조한 사례

| 사례 | 소스 기준 판정 |
|---|---|
| 작업 A 편집 전 작업 B만 갱신됨 | B의 최신 행을 보존하고 A만 편집한다. A가 바뀌었거나 중복이면 A의 편집·후속 이동을 보류한다. |
| 정규식이 표 구분선까지 삼켰거나 과거 마커가 사라짐 | 보존 대조에서 실패한다. 원문·이번 변경을 확정할 수 있고 후속 편집을 보존할 때만 영향 부분을 복구한다. |
| 완료 승인 뒤 원본만 존재하고 대상 행이 재등록됨 | 승인·원본·현재 행을 대조해 그 행만 처리한 뒤 이동한다. 원본과 목적지 양쪽이 있거나 둘 다 없거나 승인 근거가 불명확하면 보류한다. 목적지만 있는 분기의 일반 재개 연결은 위 지적과 같다. |
| 이름을 가린 업무 사례가 선택 verification의 유일한 합격 경로 | 공통 기준의 사례 의존으로 판정한다. 다른 프로젝트에 적용할 수 있는 관찰 조건으로 바꾸거나 적용 범위를 다시 확인한다. 출처 이름을 근거로 기록하거나, 공통 전제에 재사용 근거가 있거나, 프로젝트 전용 계획의 고유 계약이면 유지할 수 있다. |

위 사례는 실제 지침을 따라 판정한 결과다. 호스트의 편집 경합이나 모델의 행동을 재현하는 검사는 수행하지 않았다.

#### 검증 도중 확인한 보완

- `inject/layer2_checkpoint.md:75–86`에서 전체 대조 요청이 없으면 탐색·정리를 생략하고, 대조·보고 전용 요청에는 행을 수정하지 않는 분기를 확인했다.
- `tests/test_task_index_policy.py:68–93`에서 관련 절의 보호 문구 검사 추가를 확인했다. 추가 뒤 같은 두 테스트 모듈을 다시 실행해 23개가 통과했다. 이 검사는 지침의 존재를 확인하며, 위 사례의 입력과 예상 출력 또는 일반 재개 진입점 연결은 별도로 대조해야 한다.

### 🚨 즉시 수정 필요

- 실제 작업 파일에 손상을 일으킨 사례는 관찰하지 않았다. 위 항목은 검증 완료 판정 전에 처리해야 한다.

### 📝 조용한 결정 목록

- **의도적 위임.** Layer 0의 후보·의존성·우선순위는 설계 인계에 보존하며 INDEX 등록은 첫 설계에 맡겼다. 계획이 허용하는 인계 방식에 해당한다. 근거는 `inject/layer0_init.md:70,132,145,181`이다.
- **비가시적 위임.** 완료 처리 규칙은 목적지만 있는 경우를 정의하지만, 어떤 단서로 일반 재개 루틴에서 그 경우에 진입할지는 정하지 않았다. 같은 세션의 실패 처리와 세션이 끊긴 뒤의 재개 사이에서 결과가 달라질 수 있다.

### 🔍 에이전트 가정 검증

- **두 변경을 별도로 추적하며 하나의 승인과 동기화로 검토할 수 있다 — 유효.** INDEX 안전성과 공통 범위 점검의 상세 절차와 소비 경로가 나뉘며 source/dist 동일성 검사에서 둘 다 확인된다.
- **지침 변경은 가역적이며 체크섬·검사 결과는 동시 쓰기 방지와 모델 준수의 증거가 아니다 — 유효.** `core/agent_rules_detail.md:158`이 한계를 명시한다. 실제 호스트 편집 경합은 확인하지 않았다.
- **읽기·안내와 실제 INDEX 저장 경로를 구분할 수 있다 — 유효.** `hooks/session_start.py:94–169`는 작업 상태와 안내를 읽어 반환한다. 실제 쓰기는 기존 설계·발견·완료·Layer 2 지침에서 수행한다. 재개 진입점과 승인 전 연결 누락이 해당 구분의 효력을 제한한다.
