# 작업 계획서: Root README 사용자 흐름·기본 이해 원칙

## 요구사항 명세

### 요청 기준

사용자는 root README에 실제 소스 파일명·명령·세부 옵션을 나열하지 않고 사용자 흐름을 간략히 설명하며, 세부 내용은 개별 안내 문서로 보내는 문서 작성 원칙을 MPA 시스템에 추가하도록 요청했다. 이후 과도한 축약을 정정해, README만 읽어도 도구의 목적·적합한 사용 상황·기대 효과, 기본 구조, 설치된 프로젝트 구조와 작업·이슈 수집 흐름을 이해하도록 범위를 보완했다. 시작 예시는 설치 위치처럼 행동에 필수인 입력을 생략하지 않도록 보완했고, 작업 계획서가 계획·지시·실행·검증의 중심 문서이며 `workspace/tasks/active/[작업명]/plan.md`에서 생성·`done/`으로 보관됨을 명시하도록 보완했다. `docs/`는 완료 기능 문서에 한정하지 않고 개발에 필요한 문서와 진행 과정에서 생성된 문서를 보관하도록 바로잡았다. 다중 삭제의 원자성 강화와 리뷰 결과의 후속 작업 강제는 Git 복구 가능성과 사용자 판단을 이유로 이번 범위에서 제외했다.

### 목적

모든 미래 세션에서 root README를 사용자 진입·흐름 중심 문서로 일관되게 작성·검토하도록 한다.

### 범위·제외 범위

- 범위: `.mpa/runtime/core/agent_rules.md`에 root README의 책임 범위와 세부 문서 위임 원칙을 추가하고, 도구의 목적·사용 상황·기대 효과와 이슈 흐름·프로젝트 구조·설치된 프로젝트 구조를 포함한 현재 root `README.md`에 적용·검증한다. 같은 사실을 설명하는 설치 골격·workspace 안내·가이드북은 실제 구조와 모순되지 않도록 함께 정정한다.
- 제외 범위: 명령 계약, 배포·정리 동작, 강제적인 리뷰 후속 작업, Git 정책

### 완료 기준

- Runtime 규칙이 README만으로 도구의 목적·사용 상황·기대 효과, 사용자 흐름·기본 구조·이슈 수집 흐름을 이해하도록 작성하고, 세부 명령·파일명·옵션만 개별 안내 문서로 연결하도록 명시한다.
- 현재 root README가 해당 원칙에 맞고, `dist/.mpa/runtime/`이 source Runtime과 동기화된다.

### 사용자 결정

- root README 범위 — 사용자 흐름만 간략히 설명하고 세부 명령·파일명·옵션은 개별 설명 문서로 보낸다.
- 보완 결정 — 기본 이해를 돕는 이슈 기록·수집 흐름, 프로젝트 구조, 설치된 프로젝트 구조는 root README에 유지한다.
- 보완 결정 — 사용자가 선택할 수 있도록 도구의 목적, 적합한 사용 상황, 기대 효과를 README 앞부분에 명확히 둔다.
- 보완 결정 — 전문 문서 링크는 기본 이해를 대신하지 않으며, README만으로 구조와 흐름을 이해할 수 있게 한다.
- 보완 결정 — 시작 예시에는 설치할 프로젝트 폴더처럼 해당 행동에 필수인 입력을 명시한다.
- 보완 결정 — 작업 계획서가 사용자와 agent의 공통 기준이자 작업 재개의 기준임을 README에 명시한다.
- 보완 결정 — 작업 계획서의 생성 위치와 완료 이력 보관 위치를 README에 명시한다.
- 보완 결정 — `docs/`를 개발에 필요한 문서와 진행 과정에서 생성된 문서의 보관 공간으로 설명한다.
- 제외 결정 — 다중 삭제의 부분 실패 대비와 리뷰 결과 후속 작업 강제는 이번에 추가하지 않는다.

### 변경 불가 제약

- 사용자 문서의 정확성을 낮추거나 필요한 세부 정보를 삭제하지 않는다. 세부 정보는 적절한 개별 안내 문서에 남긴다.
- Runtime release 생성·대상 배포는 사용자 명시 요청이 있을 때만 수행한다.
