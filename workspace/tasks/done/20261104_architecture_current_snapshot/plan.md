# 작업 계획서: 아키텍처 현재 설계와 이력 분리

## 요구사항 명세

### 요청 기준
architecture 문서는 타임라인 대신 최종 버전만 유지하고 이력은 architecture_history.md로 옮기며 상단에는 이력 파일 안내만 둔다. 사용자 정정에 따라 이 방식을 MPA 시스템의 공통 규칙과 템플릿에 반영한다.

### 목적
현재 설계와 변경 경위를 구분해 다음 세션이 최신 기준을 바로 읽게 한다.

### 범위·제외 범위
shared/architecture.md 정리 및 architecture_history.md 생성. Runtime 공통 규칙·기록 위치·메모리 관리자·초기화/갱신/점검 지침과 템플릿을 보완하고 source 확인 후 dist에 동기화한다. hook 동작 변경·release/deploy·다른 프로젝트 문서·과거 Git 이력 재구성은 제외한다.

### 완료 기준
현재 문서에 날짜별 이력을 누적하지 않고 상단에 상대 링크를 둔다. 이동한 변경 경위와 원문을 이력 파일에 보존하고 현재 유효한 설계·호환 조건은 유지한다. MPA 규칙과 템플릿은 현재/이력 분리·보존 후 교체·이력의 선택적 로드·기존 문서 전환을 일관되게 안내하며 source 검증 및 source/dist 일치 확인을 통과한다.

### 사용자 결정
이력 파일명은 architecture_history.md이며 현재 문서와 같은 폴더에 둔다.

### 변경 불가 제약
현재 프로젝트의 설계와 운영 계약의 의미를 변경하지 않는다. 이력 보존 후 현재 문서를 교체한다. 과거 이력은 추정하지 않고 기존 이력 파일은 덮어쓰거나 일괄 정리하지 않는다.

### 에이전트 가정
기존 문서는 주제별 구조이므로 변경 경위만 분리하고 현재 설계의 이유·제약은 보존한다.

### 결정 대기 항목
없음.

### 작업 분류 판단 근거
단일 관심사인 문서 정리다. 분리 방식은 사용자 지정으로 설계 결정이 필요 없다. Git diff로 즉시 복구 가능하다. 파일명·배치·방향이 명확해 추가 취향 판단이 필요 없다.

## 선택 문서
추가 역할 문서 없음. 이 계획서에서 실행·검증을 관리한다.

## 설계 기준
architecture는 현재 유효한 설계의 정본, architecture_history는 변경 경위의 정본이다.
Runtime 관리 절차의 상세 정본은 core/architecture_memory.md로 분리하고, agent_rules.md는 정본 구분·필수 로드 조건을 유지한다. 현재 명세와 승인해시는 변경하지 않는다.

## 실행 계획
이력 원문을 먼저 보존하고 현재 문서의 관리 원칙·서술·배치를 정리한다. Runtime 상세 절차를 core/architecture_memory.md에 먼저 저장한 뒤 core 본문을 최소 규칙·로드 조건으로 교체한다. 기록·관리·초기화·점검 지침과 템플릿을 새 정본으로 연결하고 source 확인 후 sync-runtime으로 dist를 동기화한다.
