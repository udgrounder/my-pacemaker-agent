# 변경 이력

## 계획·결정 변경 이력

### 2026-11-04 — 프로젝트 문서 정리에서 MPA 공통 규칙 보완으로 범위 정정
- 이전 판단: 현재 프로젝트의 architecture.md와 architecture_history.md만 정리한다.
- 새 판단: 동일한 원칙이 다른 프로젝트와 후속 세션에도 적용되도록 Runtime의 공통 규칙·상세 기록 위치·메모리 관리자·초기화/갱신/점검 지침과 템플릿을 수정하고 dist를 동기화한다.
- 이유: 사용자 “mpa 시스템에 보완해야 하는거 아냐?” 정정. 기존 상세 규칙이 architecture.md에 결정 이력을 기록하도록 하여 현재 상태 관리 원칙과 충돌했다.
- 명세 영향: Runtime 지침·템플릿과 source 검증·dist 동기화를 포함한다. release/deploy와 hook 동작 변경은 제외한다.
- 승인 근거: 이번 사용자 발화는 앞서 지정한 현재 설계/이력 분리 방식을 MPA 시스템에 반영하라는 실행 지시다. 파일 배치·보존 순서가 명확하고 Git으로 복구 가능하며 단일 관심사·추가 설계 및 사용자 결정 불필요 조건을 유지하므로 minor 경로를 적용한다.

## 구현 결과

### 2026-11-04 — 독립 검토 P2 대응: 아키텍처 메모리 절차 분리
- 이전 배치: 항상 로드하는 core/agent_rules.md에 초기화·변경·이관·보존·선택적 읽기 상세 규칙을 함께 두고 소비 지침에 일부 절차를 복제했다.
- 새 배치: core/architecture_memory.md를 상세 정본으로 만들고, agent_rules.md에는 현재/이력 구분 및 필수 로드 조건만 유지한다. 소비 지침과 템플릿은 새 정본을 직접 읽도록 연결한다.
- 이유: 독립 검토에서 확인된 core 용량 회귀를 해소하고 상세 절차의 중복 관리와 참조 누락을 줄인다. 신규 파일을 먼저 저장한 뒤 기존 본문을 교체한다.
- 명세 영향: 없음. 현재 설계/이력 분리·보존 순서·기존 문서 전환·현재 위험 보존의 의미와 기존 검사 기준은 유지한다.
- 사용자 근거: 파일 분리 제안 후 사용자가 “파일 확인하고 작업 진행해줘”라고 실행을 지시했다. 추가 명세 변경이 없어 승인해시를 유지한다.
- 결과: 신규 상세 파일을 먼저 저장하고 core·소비 지침·템플릿을 새 정본으로 연결한 뒤 sync-runtime을 수행했다. 상세 규칙의 의미와 과거 실패 증거는 보존했다.
- 검증: 관련 기존 35개 검사 전부 통과, core 34,506 bytes < 기준 34,731 bytes. 전체 source/dist 일치 및 check/audit·diff 형식 검사 통과. 독립 검토자가 review_recheck.md에서 기존 P2 해소·추가 0건을 판정했다. 이전 1·2차 보고서는 재작성하지 않았다.

- 프로젝트 문서에서 이동한 원문 보존·링크·형식 확인을 완료했다.
- Runtime 공통 정본과 상세 기록 위치를 수정하고 메모리 관리자·초기화/업데이트·구현/검증·정합성 점검 지침을 연결했다. shared 작성 안내와 architecture_history_template을 추가했다.
- sync-runtime 완료. 기존 정책/계약 테스트 15개 통과, source/dist 68개 파일 일치, 승인 check/audit 정상 및 diff 형식 검사 통과. release/deploy는 수행하지 않았다.

## 독립 검토 결과 — 2026-11-04

- 사용자 검토 요청에 따라 대화를 상속하지 않는 별도 에이전트로 1차 검토와 2차 주장/원문 대조를 순서대로 수행했다. review_phase1.md, review_phase2.md, review_summary.md에 근거를 보존했다.
- 이전 15개 통과 주장은 해당 범위에서 재확인됐으나 구조 로딩 검사를 포함한 35개 실행에서는 34개 통과·1개 실패했다. core 35,310 bytes가 34,731-byte 회귀 기준을 초과하는 P2 1건이며 변경 전 HEAD는 통과한다. 추가 결함은 발견되지 않았다.
- 검증 완료 판단을 수정 필요로 정정했다. 현재 명세·제품 파일은 변경하지 않았다. source/dist parity와 이관 원문·현재 설계 보존은 확인됐다. 전체 테스트·배포·LLM의 실제 준수는 미확인이다.
