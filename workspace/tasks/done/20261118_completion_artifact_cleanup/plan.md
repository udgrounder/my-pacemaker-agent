# 작업 계획서: 완료 시 역할을 마친 검토·판단·스냅샷 정리

## 요구사항 명세

### 요청 기준
사용자 요청: “독립 비평 결과를 반영해서 작업 완료 시 불필요해진 검토 문서·판단 근거·스냅샷을 정리하는 절차를 MPA에 적용할 계획서 작성해줘.”
출처: [개선 이슈](../../../issues/20261118_task_completion_artifact_cleanup.md), [논의 제안 독립 비평](../../../exploration/discussion/20261118_task_completion_artifact_cleanup_critique.md).

### 목적
작업 완료 후 필요한 결과·결정·제약·승인·검증 결론을 유지하면서 역할을 마친 리뷰/평가 원본과 중간 판단 근거·스냅샷을 정리한다. 현재에도 필요한 정보의 유무와 원본 의존 해소를 기준으로 판단하며, 정리가 또 다른 원문 보관·요약 작업으로 늘어나지 않게 한다.

### 범위·제외 범위
범위는 MPA의 완료 보고 준비·사용자 완료 승인·보조 자료 정리·INDEX/done 이동을 연결하는 지침, 현재/과거 근거 보존 경계, major/minor와 독립 검증 기록의 수명 구분, 선택 문서/참조/승인 정합성, 검증·설명 문서·source/dist 동기화다.
현재 작업이 생성한 보조 자료와 알려진 현재 의존을 대상으로 하는 절차를 제공한다. 기존 완료 작업들의 실제 정리·파일 삭제는 이번 구현 범위에서 제외하며 별도 명시 요청으로 다룬다.
사용자 원본·제품 산출물·plan/changelog의 정본 전체 삭제, release/deploy backup·설정·기존 history-cleanup 변경, 진행 중 승인 복구/충돌 자료 정리, 새 삭제 엔진·hook·자동 카운터·영구 manifest·별도 요약 파일 의무화, 릴리즈 생성·대상 배포는 제외한다.

### 완료 기준
- C1. 지적은 메인이 현재 명세·실제 결과와 대조하여 해결됨/처리 불필요/현재 유효로 판단한다. 미확인·실패를 처리 불필요로 바꾸거나 정리를 위해 완료 기준·위험을 낮추지 않는다. 중복·잘못된 전제·이미 승인된 범위 밖 등 처리 불필요 이유는 필요한 수준으로 확인하며 자동 TODO로 만들지 않는다.
- C2. 지적 종결과 파일 전체의 역할 종료를 구별한다. 해당 파일의 현재 필요한 정보가 없거나, 필요한 정보가 적합한 정본에 저장·대조돼 원본 의존이 해소됐을 때만 삭제한다. 혼합 파일은 필요한 부분만 이관/축약하고 정리한다. 과거 사용 사실·파일명·확장자·크기만으로 보관/삭제하지 않는다.
- C3. 순서는 대상/잔존 정보 판정 → 기존 최종 문서에 최소 정보 저장 → 내용/현재 결론 대조 → 참조·등록·승인 영향 확인 → 삭제 → 실제 상태/연결 확인이다. 이관·대조·승인 영향 미해결 시 해당 원본을 삭제하지 않는다.
- C4. 완료 보고 전에 정리 범위와 남길 결론을 준비하고 사용자에게 핵심을 고지한다. 사용자 완료 확인 후 실행 전에 그 기준과 파일 상태가 여전히 같음을 대조한다. 고지된 해당 작업의 보조 자료 정리를 기존 완료 승인과 연결하며 파일마다 새 승인을 요구하지 않는다. 범위·완료 기준·위험·사용자 결정의 중요한 변경은 기존 확인/승인 경로를 따른다.
- C5. 최종 결과·핵심 결정 이유·사용자 승인·검증 결론·현재 제약/수용 위험/후속 조치를 간결하게 남긴다. 실제로 필요한 재현 입력·복구 원문·미해결 의존은 필요한 최소 부분을 구체적 이유와 함께 보관한다. 원문 전량 복제·무기한 별도 archive·새 요약/처분표를 기본값으로 만들지 않는다.
- C6. 해당 작업의 plan/changelog·선택 문서 등록·관련 최종 문서·알려진 후속 연결을 확인한다. 현재 소비하는 내용은 실제 새 정본으로 연결하고 삭제할 파일의 활성 참조·등록을 먼저 정리한다. reqspec-v1 명세 밖 기록 정리만으로 해시를 바꾸지 않으며 명세 블록/legacy 해시 영향은 기존 승인 경로를 따른다. 재승인이 없으면 영향받는 원본을 보관한다.
- C7. 원본/제품/다른 작업의 자산·release/backup·진행 중 복구 자료를 보조 자료와 구별한다. 다른 작업의 현재 의존이 확인되면 의존 부분을 먼저 이관하거나 보관한다. 대상 경로·소유·역할이 불명확하거나 외부 경로/symlink를 가리키면 삭제하지 않는다. 이번 작업 보조 자료 밖으로 일괄 탐색·삭제하지 않는다.
- C8. 단계별 실패·중단은 실제 상태로 확인한다. 삭제 실패한 파일은 미정리로 남기고 성공했다고 보고하지 않는다. 단순 삭제 실패로 보존된 불필요 원본과 정본/승인 정합성 실패를 구별한다. 후자는 완료 이동을 보류하며 전자는 기능 완료와 정리 결과를 구분해 기록·보고할 수 있다. 새 작업·추가 승인을 자동 생성하지 않는다.
- C9. 독립 비평/검증의 대화 미상속·유효 산출물 확인·1차/2차 대조는 실행 당시 유지한다. 사용자 결과 확인까지 필요한 입력을 조기 삭제하지 않는다. 그 역할이 끝나면 원본 보관 대신 기존 최종 기록에 검증 수행 방식·판정·수정/재검증 결과·남은 한계를 남길 수 있다. 원문 없이 원문 재현/재검증까지 가능하다고 주장하지 않는다.
- C10. major/minor 완료 경로·규칙의 보존 문구·독립 기록 경로가 모순 없이 연결되고 기존 승인/복구·문서 연결·크기·계약·INDEX/Layer 2·source/dist 검사를 유지한다. 정상/혼합/실패/공유 의존/승인 경계 사례와 전체 테스트 결과를 기록한다.

### 사용자 결정
파일이 한때 검증에 쓰였다는 사실만으로 영구 보관하지 않는다. 리뷰 지적 대부분이 해결됐거나 처리 불필요로 판정되면 원본과 그에 종속된 중간 근거·스냅샷도 정리하는 방향을 요청했다. 독립 비평의 최소 이관·대조·책임·참조/승인 보완을 계획에 반영한다.
계획 작성 요청 후 사용자가 “작성한 계획서대로 구현 진행해줘.”로 완성 계획서의 Runtime 변경·검증 구현을 승인했다. 과거 완료 작업의 실제 파일 정리를 승인한 것으로 해석하지 않는다.

### 변경 불가 제약
현재 실패·미확인·수용 위험·승인 근거를 정리로 숨기지 않는다. 사용자 완료 확인을 생략하거나 같은 범위의 승인 질문을 반복하지 않는다. 현재 필요한 원본을 checksum만 남기고 없애지 않는다. 기존 사용자 변경·INDEX 다른 행/과거 마커·완료 이력·immutable release를 보존한다. dist는 sync-runtime으로만 갱신한다.

### 에이전트 가정
- 정리 판단은 지적/자료의 의미와 현재 의존에 관한 작업이다. 기존 파일 도구·plan_hash·task_documents 검사와 짧은 지침으로 수행하고 새 자동 삭제 엔진을 도입하지 않는다.
- 최종 문서에 남길 최소 정보는 작업별로 다르다. 고정된 새 보고서/모든 기각 목록/별도 영구 manifest는 필요하지 않다.
- 정적 참조·사례 검사는 실제 모델의 판단·호스트 삭제 도구의 실행 준수까지 보장하지 않는다. 문서 경로 검증, 기존 도구 동작, 실제 운영 효과를 구별한다.
- 과거 done 작업의 잔존 파일을 예로 봤지만 개별 파일의 삭제 가능성을 확정하지 않았다. 이 작업에서 소급 삭제하지 않는다.

### 결정 대기 항목
없음. 아래 완료 승인 전 준비·승인 후 실행 및 예외 처리는 검토 가능한 설계안이다.

### 작업 분류 판단 근거
현재 구현은 Runtime 지침·참조·테스트/설명 문서의 가역적 변경이며 실제 기존 사용자 자료 삭제·외부 연동·공개 인터페이스 변경을 수행하지 않는다. 여러 완료/검토 경로의 의미·승인·자료 수명에 관한 설계가 필요해 major로 분류한다. 향후 실제 삭제의 비가역 가능성은 별도 독립 설계 비평의 필수 위험 신호로 다루고, 실제 작업의 권한/위험 변화에는 기존 규칙을 적용한다.

## 선택 문서
추가 역할 문서 없음. 이 plan에서 정리 기준·완료 연결·실행/검증 계획을 관리한다. 설계 비평·구현 검증 결과와 의미 있는 변경은 기존 critique/review/changelog 절차를 사용한다. 이번 설계 문서 작성만으로 이 자료를 삭제하지 않는다.

## 설계 기준

### 현재 규칙과 충돌 지점
- detail의 “계획서와 변경 이력 관리”는 현재 실패/위험·결정 이력·복구 자료 보존을 요구한다. 완료 후 역할을 마친 보조 원본과 현재에도 필요한 정보의 구분을 추가한다. plan/changelog 정본·승인 이력 자체를 폐기하는 정책으로 확대하지 않는다.
- detail의 “작업 항목 완료 처리”에는 자료 정리 단계가 없다. 완료 승인 전 준비와 확인 후 실행을 삽입하되 기존 충돌 검사→완료 승인→INDEX 한 행 제거→done 이동 순서의 안전 경계를 유지한다.
- layer1_review·layer1_critique·실행 우선순위는 검토 결과 파일의 존재·근거를 실행 완료 조건으로 삼는다. 실행 중 확인과 완료 후 원본 보관을 구별해야 한다. review의 미해결 해소·재검증 전에 원본을 지우지 않는다.
- task_documents의 등록·선택 문서가 삭제 파일을 가리키면 inspect/input 경로가 깨질 수 있다. 등록 변경과 의미 대응·승인 영향 확인을 정리보다 먼저 수행한다.
- verification_template은 결과를 review 파일에 기록하도록 한다. 결과를 만드는 시점의 위치와 사용자 완료 후 간결한 최종 결론의 위치를 구분한다.
- 공통 core는 33,556바이트이며 기준은 34,731 미만이다. 상세 정리 정책은 detail에 두고 core에는 필요한 트리거/정본 연결만 추가한다.

### 판단 책임과 파일 단위 삭제 조건
메인이 지적과 실제 결과를 대조하고 남는 유효 정보를 판단한다. “해결 확인 불가”는 미확인으로 유지한다. 처리 불필요의 사소한 중복까지 모두 영구 목록화하지 않으며, 최종 결론/위험/승인 범위에 영향을 주는 기각 이유만 기존 기록에 남긴다.

정리 후보는 현재 작업이 생성한 리뷰·평가 원본, 중간 판단 메모·추출/비교 자료·스냅샷이다. 이름은 탐색 단서일 뿐 삭제 조건이 아니다. 한 파일이 여러 지적·자료의 근거라면 현재 필요한 정보가 모두 해소/이관됐는지 확인한다. 원문에만 있는 현재 필요한 관측값·재현 입력·복구 근거가 남으면 해당 부분을 보관한다.

### 완료 흐름에 넣을 위치
1. **사용자 완료 확인 전 준비:** 검토 지적 처리를 마무리하고 최종 결과·남은 제약/위험·승인·검증 결론을 기존 문서에 간결히 정돈한다. 이번에 정리할 범위와 남길 예외를 기존 plan의 실행 기록/운영 안내 또는 완료 보고에 필요한 만큼만 밝힌다. 결과 확인에 쓰일 review 원본은 아직 삭제하지 않는다.
2. **완료 확인 후 대조:** 기존 완료 판별과 목적지 충돌 검사를 통과한 뒤 완료 승인 상태를 기록한다. 정리 대상·잔존 정보·후속 의존·현재 파일 상태가 준비 때와 같은지 재확인한다. 새로운 내용/용도/사용자 원본이 생겼거나 중요한 판정이 달라지면 그 대상은 삭제하지 않고 기존 범위/위험 처리로 돌아간다.
3. **정보 이관·참조 정리:** 필요한 최소 정보를 적합한 기존 plan/changelog/운영 안내 등에 저장하고 성공·내용 대응을 대조한다. 현재 소비하는 참조/선택 문서 등록을 실제 정본으로 연결한다. 단순 과거 이벤트에 등장하는 파일명은 역사적 참조로 구별하며 모든 과거 언급을 지우거나 전체 기록을 다시 쓰지 않는다.
4. **승인 영향 확인:** 명세 밖 기록·등록 정리는 기존 해시를 유지한다. reqspec-v1 명세 블록 링크/내용이나 legacy 본문 해시에 영향이 있으면 기존 확인·갱신/복구 규칙을 따른다. 삭제를 위해 해시를 임의 갱신하거나 재승인을 기계적으로 요구하지 않는다. 필요한 승인이 확보되지 않으면 해당 원본을 남긴다.
5. **삭제·사후 확인:** 해당 작업 안의 확인된 보조 일반 파일만 기존 도구로 정리한다. 사용자 원본·제품/다른 작업 자산·release/backup·진행 중 복구 자료·외부/symlink·역할 불명 자료는 이 흐름에서 삭제하지 않는다. 삭제 직전 상태가 달라졌거나 다른 writer가 작업 중이면 해당 대상을 보존하고 재판정한다. 원자적 파일시스템/동시성 보장을 주장하지 않는다.
6. **INDEX/done·후속:** 정본·승인·필수 연결이 유효하면 기존 순서로 INDEX에서 해당 행만 제거하고 목적지를 재확인해 done으로 이동한다. 정리가 일부 실패해 불필요 원본만 남았으면 미정리 범위/이유를 짧게 기록하고 기능 완료와 구별해 보고한다. 정본·승인/이관 무결성이 불명확하면 이동을 보류한다. 기존 Layer 2 제안·memory/문서 반영을 유지하고 점검을 자동 실행하지 않는다.

### 최소 최종 기록과 정리 한계
최종 기록은 결과·핵심 결정 이유·승인·검증 수행/판정·수정 후 재검증·현재 한계·운영 제약을 작업에 필요한 만큼만 담는다. 상세 문서를 다른 이름으로 통째로 복제하지 않는다. 원문을 없앤 뒤 남은 기록으로 과거 원문 대조가 가능한 것처럼 쓰지 않는다. “원문은 역할 종료 후 정리, 최종 결론은 이 위치”라는 사실을 필요한 기존 기록에서 설명할 수 있다.

비평/검증 상세·일회성 snapshot은 실행 당시 역할이 끝난 뒤 이 원칙을 적용할 수 있다. 정리가 독립 검증의 실제 수행·유효 산출물 확인을 대신하지 않는다. 실제 복구가 끝난 일시 자료는 기존 복구 절차의 대조·정리를 먼저 따르고 무기한 보호 자산으로 만들지 않는다.

### 참조 확인 범위
해당 작업의 plan/changelog·등록 문서·관련 최종 문서·알려진 후속 연결에 한정한다. 다른 작업의 현재 의존을 발견하면 그 부분만 먼저 이관하거나 보관한다. 숨은 참조를 완전히 찾기 위해 done 전체를 읽지 않는다. 기계적 링크 부재를 의미상 의존 부재의 증명으로 사용하지 않는다. Git에 복원 가능한 원문이 있다고 확인 없이 가정하지 않는다.

### 반례와 완화
- 검토 파일 일부만 종결됨 → 현재 필요한 정보가 정본에 저장·대조될 때까지 파일 전체 삭제를 보류한다.
- 과거 실패를 불필요로 분류해 성공으로 정리함 → 현재 결과와 완료 기준을 대조하고 실패/미확인은 남긴다.
- 이관 저장 실패/동시 변경 → 해당 원본을 보존하고 실제 상태에서 재개한다. 성공한 이관을 중복 생성하지 않는다.
- 링크만 지우고 필요한 결론도 사라짐 → 최종 기록의 내용 대응과 알려진 현재 의존을 삭제 전에 확인한다.
- 승인 명세 링크 변경을 기록 정리로 숨김 → 기존 승인/해시 검사 경로를 유지하고 승인 미확보면 해당 삭제를 보류한다.
- 모든 자료를 archive·새 요약으로 옮김 → 현재 필요한 최소 정보만 기존 정본에 남기며 정리 때문에 새 보관 체계를 만들지 않는다.
- 이 절차를 기존 done 일괄 정리 권한으로 해석함 → 사용자 명시 요청 없는 소급 정리 금지와 현재 작업 범위를 명시한다.

### 생략 항목과 사유
외부 기술 조사·UI·설정·새 자동 삭제 CLI/hook은 의미 판단 절차 적용에 필요하지 않아 생략한다. 역할 문서 분리는 이 plan에서 기준을 관리할 수 있어 생략한다. 과거 완료 작업의 실제 삭제 실험·원문 전량 백업·삭제별 영구 manifest·모든 파일별 새 승인·실제 모델 장기 준수 측정은 이번 완료 기준이 아니다.

## 실행 계획
1. **정본/소비 경로·충돌 문구 대응:** 승인 후 baseline과 기존 수정분을 확인하고 완료 보고·검토·minor·독립 결과 확인·등록/승인·보존 문구의 대응표를 만든다. 이유: 검증 중 필요한 근거와 완료 후 역할 종료를 모순 없이 구별한다.
2. **상세 정리 정책과 완료 연결:** core의 조건부 트리거와 detail의 정본·완료 승인 전 준비/후 실행·정보 이관·삭제/실패 경계를 작성한다. 기존 완료 충돌 검사·INDEX/done·Layer 2 연결을 유지한다. 이유: 정보 손실 방지 순서와 간결한 정리를 함께 구현한다.
3. **단계/템플릿/최종 기록·설명 정합성:** 관련 소비 경로와 원본 보존 문구를 정리하고 독립 검증 원본의 수명·현재 입력 등록·최소 결론을 연결한다. 문서·architecture는 이력 저장 후 동기화한다. 이유: 상세 정책만 추가하고 기존 “원본 유지” 지시가 남는 충돌을 막는다.
4. **정적 회귀·기존 도구·시나리오 검증:** source/dist 동기화 후 아래 정상/실패/경계와 실제 참조 단절 fixture·관련 기존 승인/연결 검사·전체 테스트를 수행한다. 이유: 단순 문구 존재만으로 안전한 삭제 행동을 입증했다고 하지 않으며 기존 보호 경계의 회귀를 확인한다.
5. **독립 구현 검증·결과 보고:** 대화 미상속 1차 기준/실제 소스 검증 후 별도 2차에서 변경 이력·주장을 대조한다. 지적을 수정·재검증하고 결과와 한계를 보고한다. 사용자 결과 확인 전 이 작업의 검토/스냅샷을 삭제하거나 done으로 옮기지 않는다.

| minor와 정리할 자료 없는 작업 | 동일 안전 원칙, 별도 리뷰/요약/목록·새 승인 절차 강제 없음 |
| 정본/소비 연결·순서·보호 문구 삭제 fixture | 실제 Runtime 검사와 같은 helper에서 연결/보호 누락 검출 |
| 정리 없는 기존 완료·INDEX/done/Layer 2·승인/복구 | 기존 사용자 승인·충돌 방지·다른 행/과거 마커·계약 유지 |

- 정본의 조건부 로드·실제 소비 참조는 기존 structure_loading helper를 확장해 source/dist와 메모리 fixture에서 같은 검사로 확인한다. 존재하는 다른 유효 섹션 오연결·출발 참조 삭제·순서 단절도 포함한다.
