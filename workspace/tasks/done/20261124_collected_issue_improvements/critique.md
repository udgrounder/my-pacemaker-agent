## 비평 결과

### 🚨 실패 시나리오

1. **[높음] Codex 명령이 실행 cwd를 바꾼 뒤 입력에 cwd가 없으면 상대 파일이 다른 파일로 해석된다.** 하위 폴더 `sub/`에서 `src/a.py` 요청을 보내고 hook JSON에 cwd가 없다고 하자. 현재 생성 명령은 루트를 찾은 뒤 `cd "$root"`를 수행한다(`install.py:68–74`). 계획의 「설계 기준 A」는 입력 cwd가 없으면 프로세스 cwd를 쓰도록 하므로 이 형태를 유지하면 `sub/src/a.py` 대신 루트의 `src/a.py`를 판정한다. 더 심각하게 `workspace/...` 같은 상대 요청은 잘못된 허용 prefix에 들어갈 수 있다. 「검증 기준 A1/A2」의 cwd 누락 테스트가 직접 Python 실행으로만 구성되면 생성 명령의 정보 손실을 발견하지 못한다. **보완:** 명령이 호출 전 cwd를 보존하도록 하거나 cwd를 바꾸지 않고 스크립트를 실행한다는 계약을 A에 명시한다. 하위 cwd·JSON cwd 누락·상대 경로를 결합하여 *생성된 Codex 명령 전체*를 실행하고, 같은 실제 파일의 절대 경로 요청과 동일한 판정인지 확인한다. 단순한 루트/하위 실행 결과 동일성 외에 실제 판정 대상도 대조한다.

2. **[중간] 기존 설정 갱신 저장이 실패하면 사용자 hook을 함께 잃을 수 있다.** 새 계획은 기존 설정을 읽기만 하던 멱등 경로를 실제 교체 경로로 넓힌다(「설계 기준 A」의 기존 관리 명령 갱신). 현재 `wire_hooks()`는 설정 파일에 직접 `write_text()`한다(`install.py:423–426`). 쓰기 도중 실패하면 기존 파일이 잘리거나 불완전해져 관리 명령 외 사용자 hook까지 손상될 수 있다. A3의 설정 보존 검증에는 저장 실패가 없다. **보완:** 저장 실패 시 기존 설정이 그대로 남고 갱신 실패를 보고한다는 최소 실패 계약과 실패 주입 검증을 추가한다. 임시 파일·교체 등 구체 수단은 구현자가 결정할 수 있으며 설치 전체에 대한 새 transaction 체계를 요구하는 지적은 아니다.

### ⚠️ 숨은 가정 (파급효과 높은 순)

- **호스트 입력 cwd 누락 시에도 최초 실행 cwd가 hook 프로세스에 남아 있다는 가정.** 「에이전트 가정」은 호스트별 입력 차이와 cwd 유무를 다루지만, 「설계 기준 A」의 fallback이 유효하려면 생성 명령이 cwd를 보존해야 한다. 현재 Codex 명령은 이 전제를 깨뜨린다. 위 실패 시나리오 1의 실행 계약과 결합 테스트가 필요하다.
- **설정의 성공적인 메모리상 병합이 사용자 설정 보존을 의미한다는 가정.** 「변경 불가 제약」과 A3의 보존 범위는 저장 과정에도 적용되어야 한다. 현재 직접 저장 방식은 이를 보장하지 않는다. 위 실패 시나리오 2와 같이 실패 시 원본 보존을 완료 판단에 포함해야 한다.

### ❓ 미해소 비가시적 위임

- **[중간] 루트 판정 오류의 허용·경고·차단 결과가 구현 중 결정되도록 남아 있다.** 「설계 기준 A」는 루트 식별 불가·다른 프로젝트·루트 밖 경로에 대해 “기존 fail/warn 정책과 선택 critical 보호를 유지하는 오류 처리를 설계·검증”한다고만 한다. 현재 `code_gate.py:341–343`은 off에서 입력 전 종료하고, `:363–366`은 선택 critical 무결성 오류를 별도로 차단한다. 루트 식별 실패로 critical 상태 자체를 읽을 수 없을 때 warn으로 통과할지 차단할지, 경계 밖 요청과 단순 식별 실패를 같은 결과로 볼지가 정의되지 않았다. 이는 helper 함수 이름 같은 기술 취향과 달리 승인 보호와 정상 작업의 차단 여부를 바꾼다. **보완:** 구현 전 소수의 오류 종류별로 warn/block/off에서의 결과와 critical 확인 불가 처리를 명시하고 그 표를 검증의 기대값으로 사용한다. 사용자 결정을 일괄 새로 요구할 필요는 없으며 기존 정책에서 도출 가능한 결과는 Agent가 근거와 함께 확정한다.

### 🔧 구조적 문제

- **단계 1의 명령 생성과 경로 helper 사이에 cwd 전달 계약이 선행되어야 한다.** 「실행 계획 1」이 두 변경을 묶고 있지만 서로 독립적인 정상 테스트만 통과해서는 A1을 입증하지 못한다. 명령 실행 후 helper가 받는 원래 cwd와 Runtime 소유 루트를 먼저 구분하고 위 결합 테스트를 단계 1의 완료 근거로 삼아야 한다. 근거: 「설계 기준 A」의 상대 경로 절대화 규칙, `install.py:68–74`.
