## 판정

잔여 결함 **1건(P2)**. 기존 구현·검증 연결은 보완되었으나, 테스트 중인 기존 작업을 새 세션에서 재개하는 경로가 남는다.

### P2 — 테스트 중 재개 시 원인 확인 지침의 로드 경로가 없다

- 근거: `.mpa/runtime/core/agent_rules.md:163`은 active 작업 맥락 라우팅을 우선하며, `:169-171`은 구현 중에 `layer1_implement.md`, 검증 중에 `layer1_review.md`를 연결하지만 테스트 중에는 inject를 `—`로 둔다. 세션 시작 상태 안내도 `:128`에서 사용자 확인 대기만 가리킨다. 신규 요청 예외 `:175-178`은 현재 작업과 무관하거나 범위 밖인 경우이므로 같은 범위 버그에는 적용되지 않는다.
- 반례: active plan이 `테스트 중`인 새 세션에서 사용자가 승인 범위 안의 같은 기능에 대해 “테스트하니 여전히 실패한다. 고쳐줘”라고 보고한다. 현재 맥락 라우팅은 테스트 대기로 진입한다. 이때 `layer1_review.md:171-172`의 원인 확인 참조를 읽으라는 연결이 없고 신규 bug_fix 라우팅도 선택되지 않는다. 이어서 실패한 첫 수정의 가설을 유지한 채 추가 수정하는 경우에도 재조사 기준을 로드하는 경로가 보장되지 않는다.
- 영향: 같은 세션에서 이미 review 지침을 읽은 경우는 보완되지만, 테스트 단계 재개에서는 기존 P2의 일부가 계속 성립한다. 원인 확인 절 자체에 적용 범위를 선언한 것만으로 해당 절을 읽지 않는 진입점의 누락은 해소되지 않는다.
- 권장: core의 기존 작업 라우팅에서 테스트 중 버그 수정 보고에 한해 `layer1_review.md` 또는 `workflows/bug_fix.md`의 원인 확인 절을 읽도록 연결한다. 단순 테스트 대기 전체에 major 절차·새 작업·추가 승인을 강제할 필요는 없다.
- dist 대응본도 바이트 일치하므로 같은 결함을 포함한다.
