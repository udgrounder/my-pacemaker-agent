## 정상·실패·예외 경로 추적

- 정상 완료: 유효한 완료 확인 → 공통 완료 정본 로드 → 중복/목적지 확인 → 완료 승인 상태 → INDEX 해당 active/hold 행 제거 → 이동 직전 목적지 재확인 → done 이동. minor와 major에 모두 연결된다.
- 실패 완료: done에 동명 기록이 이미 있으면 상태·INDEX 변경 전에 양쪽 기록 보존 후 중단·차이 보고. 충돌을 해소했더라도 이동 직전 재확인하며 중첩 이동으로 우회할 수 없다.
- 질문 예외: 테스트 중 “이 값은 왜 이래?”는 검토 진입에서 구현 영향 검사에 연결되고 우선 답변한다. 명세에 값이 없다는 이유만으로 변경할 수 없다. 이미 위임된 실행 보완이면서 명세·위험이 유지되면 새 승인을 반복하지 않는다.
- 조사 예외: 타입 동적 참조나 운영 제약을 확인할 수 없으면 미확인 범위/가정·영향을 남기고 기존 위험·승인 기준을 적용한다. 미확인을 근거로 순환이 없다거나 제외 가능하다고 단정하는 경로는 없다.
- 신규 버그 실패: 접근 가능한 응답·로그·소스 중 근거로 가설을 확인하고 반증 시 재검토하며, 모든 버그에 서버 소스 열람이나 로그 추가를 강제하지 않는다. 기존 작업 안의 동일 실패 경로는 위 P2 때문에 연결되지 않는다.
- 기존 확장 지점 부적합: 조사 결과 기존 구조가 요구사항에 맞지 않으면 재사용을 강제하지 않는다. 필요한 변경의 위험·명세 영향을 기존 기준으로 판단한다.
