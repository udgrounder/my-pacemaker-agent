## 구현 내역

- Runtime 위임 판단의 정본과 JSON 판단 도구를 추가했다. 최초·현재 직접 허용 집합, 호스트/세션/역할/설정 근거, 호출 설정, 단일 수정자, 트리 슬롯·논리 작업별 복구를 입력에서 대조한다.
- 설계·구현·비평·검증·역할 문서 소비 경로와 Codex 안내를 연결했다. core의 짧은 활성화 지시는 판단 도구 검사와 읽기 전용 호출 확인 뒤 추가했다. 설치별 정책 파일은 쓰지 않았다.
- 호스트 확인은 기본 역할, 모델·추론 override 생략, 대화 미상속으로 정해진 Markdown 제목만 읽는 호출이었다. 요청은 상속이며 응답은 제목/절을 반환했다. 실제 모델 ID 메타데이터가 없어 실제 모델은 미확인이다. 하위 모델 운용을 활성화하지 않았다.
- 1차 검토의 최초 상한 증거 교체와 미래 승인 시각 허용 사례를 보완했다. 메인 기록의 최초 revision과 관찰 구간을 맞추고, 미래 관계 확인 및 호출과 확인 기록의 추론 설정 차이를 거부한다.
- 1차 검토 뒤 1차 프롬프트도 review1 승인·설계 발췌만 받도록 정리했다. 호스트 반환 근거에서 상한 밖 실제 모델이 확인된 경우, 완료 산출물도 미확인으로 두고 기존 독립 검증 실패 경로를 적용하도록 명시했다.
- 전체 267건 통과. Runtime source/dist 파일 일치, 양쪽 TOML 계약, plan 승인해시와 입력 연결, diff 확인. 정적 참조 검사와 판단 로직 테스트는 호스트 호출 강제를 입증하지 않는다.

- 2차에서 1차 프롬프트 외의 필수 읽기 목록과 체크리스트에도 구형 전체 plan·실행 step 지시가 남은 것을 확인했다. 1차는 승인·설계 발췌와 지정 실제 소스, 2차는 실행 기록과 1차 결과 대조로 일치시켰다.
