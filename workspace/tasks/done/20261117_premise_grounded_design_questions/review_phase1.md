# 1차 독립 구현 검증

## 대상·입력·판정 범위

기준 입력은 `python3 .mpa/runtime/hooks/task_documents.py inputs workspace/tasks/active/20261117_premise_grounded_design_questions/plan.md --stage review1` 출력이다. 구현 대화, plan 전체·진행·실행 기록, changelog, 전체 git diff는 읽지 않았다.

검증 대상은 source `.mpa/runtime/`의 `core/agent_rules.md`, `inject/layer1_design.md`, `inject/plan_interview.md`, `skills/analysis/silent_decision_extraction.md`, `skills/analysis/counterexample_finding.md`와 각각의 `dist/.mpa/runtime/` 대응 파일이다. 아래 상대 경로와 줄번호는 source 기준이며 dist도 동일하다. architecture.md, 검토자 persona, 실행 우선순위·작업 문서 입력 계약, 경로 추적·반례 탐색 방법을 참조했다.

판정: 공통 행동 지침은 문서상 정합하며 즉시 수정할 실질적 결함은 발견하지 못했다. 기존 검사 하나는 실패했으므로 전체 검사 통과를 선언할 수 없다. 실제 모델 행동 실험은 수행하지 않았다.

### 실제 검사

테스트는 각각 `python3 -m unittest discover -s tests -p '<파일명>'`으로 실행했다.

| 검사 | 관찰 결과 |
|---|---|
| test_policy_consistency.py | 15개 통과 |
| test_task_documents.py | 20개 통과 |
| test_contract_reference.py | 13개 통과 |
| test_structure_loading.py | 5개 중 4개 통과, core 크기 1개 실패 |
| source/dist parity | structure_loading의 전체 Runtime 상대 파일 목록·내용 일치 검사 통과. 대상 5개 개별 byte 비교도 모두 동일 |
| 대상 Runtime 10개 파일 git diff --check | 종료 0, 출력 없음 |
| 프로젝트 특화 내용 잔존 | 대상 전체 문구 확인과 `캠핑|camping|원천|부모|품목|행 단위` 보조 검색에서 개별 업무 모델을 공통 정책으로 옮긴 문구를 찾지 못함. 범용 문서·데이터 계약·핵심 사실·현재 범위 표현 사용 |

검사는 Runtime 대상 파일로 제한했다. parity는 현재 내용의 동일성을 확인할 뿐 sync 명령 실행 이력이나 외부 설치본을 증명하지 않는다.

## 주의 필요

1. `tests/test_structure_loading.py:70–72`의 core 크기 검사가 실패했다. 현재 core는 36,783바이트이고 기준은 34,731바이트 미만이다. HEAD의 같은 Runtime 파일은 34,506바이트다. 현재 전제 확인 공통 문구(core 63행, 개행 포함 382바이트)를 제외한 계산값도 36,401바이트이므로 이 문구 하나가 실패 전체의 원인이라고 단정할 수 없다. HEAD와 현재 차이에는 다른 미커밋 변경이 섞일 수 있으며 이번 변경 직전 baseline은 미확인이다. 전체 검사 통과를 선언하지 말고 현재 초과와 원인 분리 한계를 보고해야 한다. 다른 규칙을 삭제하거나 기준을 높이지 않았다.
2. 실제 모델의 반복 행동 준수는 미검증이다. 사례 경로 정합성과 단위 테스트가 장기간의 질문 품질을 보장하지 않는다. 이는 명세의 범위 제한과 일치한다.
3. core 공통 원칙과 단계·기법 적용 절차의 일부 중복은 직접 사용 경로를 보장한다. 현재 의미 충돌은 없으나 이후 수정 시 전제 변경·유효 결정 유지·중요 위험 예외를 함께 대조할 필요가 있다.

## 즉시 수정 필요

이번 전제 확인 지침의 문구·참조·판단 경로에서 즉시 수정할 실질적 결함은 발견하지 못했다. 기존 검사 실패를 성공으로 완화하지 않고 위 주의 항목에 남긴다.

## 조용한 결정

- 고정 라벨·새 문서를 만들지 않은 선택은 design 86행, interview 23행, silent 45행, counterexample 70행에서 확인된다. 별도 양식·가정별 승인을 만들지 않는 설계 기준과 맞는다.
- 자료 부족 시 독립 부분을 계속하는 선택(design 87행)은 의존 설계 확정 금지와 병행한다. 질문 최소화와 연쇄 확대 방지를 동시에 충족한다.
- 광범위한 후보·반례 탐색 프롬프트를 유지하고 출력 활용에만 적용 판단을 둔다(silent 29–49행, counterexample 30–73행). 탐색 자체 축소를 피하는 명세와 맞는다.
- 자연어 지침과 기존 승인·이력을 재사용하며 대상 내용에 새 hook·schema·자동 차단·상태·승인 gate를 도입하지 않았다.

## 가정 검증

- 원 이슈의 개별 업무 사실을 새로 판정하지 않았다. 공통 Runtime만 검토했으며 원 프로젝트 데이터 진위는 범위 밖이다.
- 공통 원칙·단계 절차·분석 직접 경로 분리는 architecture.md의 메타/단계/방법 도메인 구분과 일치한다. 세 진입 경로를 각각 추적해 문서상 누락을 확인했다.
- 전제 변경이 모든 기존 승인을 자동 무효화한다는 가정은 채택하지 않았다. 실제 문구는 관련 항목만 재검토하고 유효 결정을 보존하며 의도·중요 위험 변경에 기존 승인을 적용한다.
- 미확인 위험은 질문할 수 없다는 해석은 실제 문구와 맞지 않는다. 영향·관련성을 밝히고 기존 의도·위험 기준에 따라 필요한 결정을 질문할 수 있다.
- source/dist 동일성과 문서 대조가 모델 행동 준수를 입증한다는 가정은 기각한다. 확인 범위는 현재 문서·파일 정합성과 기존 검사 결과까지다.
