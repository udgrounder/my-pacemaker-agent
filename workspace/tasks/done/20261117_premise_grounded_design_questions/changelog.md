# 변경 이력

## 계획·결정 변경

### 2026-11-17 — 프로젝트 사례와 공통 적용 범위 분리
- 계기: 사용자가 범위·제외 범위에 프로젝트 특화 내용이 포함되어 있음을 지적했다.
- 이전 판단: 범위·제외 범위에 “campingtalk-proj의 거래·수수료·배분·끝전 업무 규칙과 해당 프로젝트 docs/tasks/memory 수정은 제외한다”를 명시했다. 검증 사례도 “거래별 확정 값”과 “배분·끝전 질문”을 사용했고 가정에는 “거래 데이터 자체에 대한 새 판단을 추가하지 않는다”를 기재했다.
- 새 판단: 범위는 프로젝트에 독립적인 MPA 공통 행동 원칙으로 한정하고 제외 범위도 개별 프로젝트의 업무 규칙·데이터 모델·프로젝트 자산 변경으로 일반화한다. 검증 사례와 가정의 도메인 표현도 일반화하고 프로젝트 식별자는 요청 기준의 출처 링크에만 둔다.
- 이유: 사례의 도메인 표현이 공통 규칙의 적용 대상이나 검증 요건으로 오해되지 않게 한다.
- 명세 영향: 미승인 계획의 범위·제약을 일반화해 명확히 하는 변경이다. 공통 원칙 세 가지와 중요 반례 검토 유지라는 사용자 의도, 구현 대상·완료 기준·승인 대기는 유지한다.
- 승인/증빙: 사용자 발화 “범위와 제왼 범위에 프로젝트 특화 내용이 포함되어 있어 확인해줘”. 구현 승인은 없으며 승인해시는 빈 값으로 유지한다.
- 과거 점검 결과의 한계: 최초 문서 연결 검사는 통과했지만 프로젝트 사례와 공통 범위의 분리를 확인하지 못했다. 이번 정정 후 별도로 대조한다.
