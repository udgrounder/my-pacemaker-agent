## 요구사항 명세

### 요청 기준

완료된 규칙 거버넌스 감사에서 남은 보완 후보인 OpenAgent 지원 범위, 외부 용어 근거 표기, MPA 시스템 파일 수정 원칙의 표현을 보완한다.

### 목적

사용자가 설치·용어·규칙을 실제 지원 범위보다 넓게 해석하지 않게 하면서도, agent가 사용자 의도에 맞는 승인된 방법론 수정을 불필요하게 회피하지 않도록 한다.

### 범위·제외 범위

- 범위: OpenAgent를 실험적·수동 설정 지원으로 명시하는 설치 안내·agent spec·가이드 문구.
- 범위: 외부 용어 제안에 `공식 출처 확인`·`내부 정의만 확인`·`미검증` 근거 레이블을 쓰는 감사·용어 규칙.
- 범위: MPA 시스템 파일 수정 원칙을 “원칙적으로 issue→review, 예외적으로 사용자 승인된 작업 항목에서 직접 수정”으로 명확화.
- 범위: Runtime source 변경 후 테스트, release, release audit, 독립 설치본 업그레이드 검증.
- 제외 범위: OpenAgent 진입점·hook 자동 연결 구현, 기존 설치본·과거 계획서 자동 변환, agent 설정 파일 변경.

### 완료 기준

- 설치 선택·도움말·README·guidebook·OpenAgent spec이 OpenAgent의 실험적·수동 설정 범위를 같은 의미로 설명한다.
- 외부 용어를 표준 또는 적합한 용어로 제안할 때 근거 레이블과 적용 기준이 정본 규칙에 있다.
- MPA 직접 수정의 기본 경로와 사용자 승인 예외가 하나의 짧은 문장으로 설명되고, 기존 release 절차와 충돌하지 않는다.
- source/dist가 release 도구로 동기화되고, 테스트·release audit·독립 설치본 검증이 통과한다.

### 사용자 결정

- 감사의 세 보완 후보를 모두 반영한다.
- 확인되지 않은 OpenAgent 통합을 구현하지 않고, 현재 동작에 맞는 실험적·수동 설정 지원으로 표시한다.

### 변경 불가 제약

- `dist/.mpa-workspace/`를 직접 편집하지 않고 `prepare-release`로만 동기화한다.
- OpenAgent를 정식 자동 연결 지원으로 표시하거나, 확인되지 않은 설정 경로·hook 계약을 추정해 추가하지 않는다.
- Runtime 배포는 immutable release·dry-run·승인·rollback 책임자 절차를 유지한다.

### 에이전트 가정

| 가정 | 근거 | 틀렸다면 |
|-----|------|---------|
| OpenAgent 선택지는 유지하되 실험적·수동 설정으로 표시하는 것이 안전하다 | config map이 없고 spec의 진입점·hook 계약이 미확정이다 | 선택지를 제거하거나 실제 wiring을 구현하는 별도 작업 항목으로 분리한다 |
| 외부 용어 근거 레이블은 감사·용어 제안에만 적용하면 충분하다 | 코드·배포 계약까지 외부 표준으로 재검증하는 범위는 이번 요청에 없다 | 레이블 적용 대상을 별도 규칙으로 확장한다 |

### 예상 조용한 결정

- OpenAgent의 상태 표기는 “실험적·수동 설정”으로 통일한다. “정식 지원” 또는 “미지원”으로 단정하지 않는다.
- 외부 용어 레이블은 인용 자체를 강제하지 않고, 근거 상태를 드러내는 최소 메타데이터로 둔다.

### 반례 (이 계획이 실패할 수 있는 시나리오)

- “실험적” 표기가 선택 자체를 불가능하게 만든다고 오해된다 → 선택지는 유지하고 자동 wiring이 없다는 사실만 명시한다.
- 근거 레이블이 외부 출처를 반드시 검색해야 하는 절차로 확대된다 → 감사·용어 제안에만 적용한다고 정의한다.
- MPA 직접 수정 예외가 승인 없는 변경 허용으로 읽힌다 → 사용자 승인된 작업 항목·release 절차를 함께 명시한다.
