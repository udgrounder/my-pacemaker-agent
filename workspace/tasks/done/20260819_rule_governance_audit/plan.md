# 태스크 계획서: 규칙·용어·제약 거버넌스 감사

**파생 출처:** 사용자 요청 — 현재 프로젝트 전반의 규칙 품질을 검토하고 개선 후보를 식별

---

## 요구사항 명세

### 요청 기준

현재 프로젝트를 검토하여 다음을 식별한다.

- 잘못됐거나 서로 충돌하는 규칙
- 더 정확한 표준 용어가 있는데 부정확하게 쓰였거나 혼동될 수 있는 표현
- 간결하고 명확한 정식 용어가 있는데 설명형 문장으로 길게 표현한 부분
- 목적·위험·집행 가능성에 비해 불필요하게 강한 제한

### 목적

MPA의 실행 규칙과 사용자 문서가 같은 개념을 같은 경계와 용어로 설명하도록 만든다. 체계는 사용자를 절차로 제한하는 것이 아니라, agent가 사용자의 명확한 의도에 맞게 작업하도록 돕는다. 암묵지·가정·범위를 계획서에 드러내 agent의 독단적 방향 이탈을 막고, 준수 비용만 높이거나 같은 확인을 반복하는 규칙은 근거를 갖춘 완화·통합·삭제 후보로 제시한다.

### 범위·제외 범위

- 범위: `.mpa-workspace/`의 실행 규칙·inject·persona·workflow·hook 메시지, `MAP_PRODUCT_RULES.md` 및 `map-product-rules/`, `workspace/project_rules.md`·현재 메모리, 설치 진입점·배포본(`dist/.mpa-workspace/`), README·guidebook·agent spec의 사용자 대면 설명.
- 범위: 규칙 간 우선순위, 트리거, 상태 전이, 승인·제약 표현, 핵심 용어, 집행 방식과 예외 규정을 교차 검증한다.
- 범위: 배포본이 설치·Runtime update·rollback에 필요한 실행 파일, 진입점, 버전·manifest 계약, 사용자 안내를 빠짐없이 갖추고 있는지 확인한다. 현재 release 산출물이 없으면 `dist/`를 배포 기준본으로 삼는다.
- 제외 범위: 이번 태스크에서 규칙을 직접 수정하거나 release/deploy하지 않는다. `workspace/tasks/done/`은 현행 판단 근거가 부족할 때만 참조하며 과거 이력의 소급 수정은 하지 않는다.

### 완료 기준

- 각 발견 사항이 정확한 위치·인용 가능한 근거·영향·권장 조치와 함께 기록된다.
- 동일 개념의 용어 혼용과 정의 누락을 용어별 매트릭스로 제시한다.
- 설명형 표현은 의미 보존 여부와 독자 이해도를 검토해, 더 짧고 확립된 용어로 치환할 후보를 별도 제시한다.
- 각 제한은 목적·위험·집행 가능성·준수 비용·대안을 기준으로 유지/완화/통합/삭제 후보로 판정한다.
- 사용자 확인 규칙은 사용자의 의도·가치·완료 판단을 실제로 보호하는지, agent 자율 실행 규칙은 계획·기록·검증으로 의도 정렬을 유지하는지를 함께 판정한다.
- 실행 레이어와 설명 레이어의 판정 기준을 구분하고, source와 `dist`의 동기화 상태를 별도 확인한다.
- 배포본의 파일 구성과 설치·업데이트 경로를 대조해, 필요한 자산의 누락·잘못된 포함·문서 안내 누락을 식별한다.
- 규칙 충돌의 우선순위와 판정 근거를 발견 사항마다 남기고, 사용자 의도가 명확하지 않아 결론을 정할 수 없으면 사용자에게 질문한다.
- 수정 제안은 승인 전에는 적용하지 않고, 즉시 조치/후속 태스크/기록만으로 우선순위를 나눈 최종 감사 보고서를 제공한다.

### 사용자 결정

- 규칙의 목적은 사용자 제한이 아니라 사용자 의도 정렬과 agent의 방향 이탈 제어다.
- 사용자 의도·가치 판단·완료 판단이 필요한 지점에는 확인 경로를 두되, 계획 범위 안의 가역적 실행·조사·기록은 agent가 불필요하게 멈추지 않고 진행하게 한다.
- 감사 결과의 실제 규칙 변경 여부와 우선순위는 최종 보고 후 사용자가 결정한다.

### 변경 불가 제약

- 감사 중 `.mpa-workspace/`, `dist/`, 배포 산출물, release receipt, 과거 태스크 이력을 변경하지 않는다.
- source 전용 map-product 규칙과 Runtime 배포 규칙의 소유 경계를 혼동하지 않는다.
- **읽기 전용 감사**는 감사 대상인 제품 규칙·Runtime·배포 산출물을 변경하지 않는다는 뜻이다. 감사 태스크 폴더의 `audit_report.md`·`critique.md`와 현재 태스크를 표시하는 `workspace/tasks/INDEX.md` 기록은 허용하며, 이 기록은 감사 증거이지 대상 규칙의 변경이 아니다. 시작 시 Git HEAD·작업 트리 상태·대상 파일 목록·적용한 배포 기준본을 기록하고, 종료 시 허용된 감사 기록 외 대상 파일 변경이 없음을 다시 확인한다.
- 감사 중 허용하는 작업은 파일 읽기, `rg` 검색, `git diff`·checksum 비교, 정적 참조 체인 추적뿐이다. `prepare-release`, `deploy`, `rollback`, `sync-runtime`, `install`처럼 상태를 바꿀 수 있는 명령은 실행하지 않는다. 동작 실행이 필요한 검증은 대상 프로젝트 밖의 임시 복제본에서 dry-run 또는 정적 계약 검증으로 제한한다.

### 예상 조용한 결정

- “표준 용어” 판단: 프로젝트 내부 정의가 명확하고 외부 계약이 없으면 내부 정의를 우선하며, 혼동 가능성만 보고한다.
- 설명형 표현: 약어·전문 용어가 오히려 낯선 독자의 이해를 해치면 설명을 유지하고, 용어+짧은 설명이 필요한 경우는 최초 1회 병기를 권고한다.
- 중복 규칙: 내용이 완전히 같은 경우 한 곳을 정본으로 권고하되, 실행 안정성을 위한 의도적 중복(source↔dist·hook 메시지)은 결함으로 분류하지 않는다.
- 의도적 중복: 아키텍처·manifest·설치/배포 명령 계약 중 하나에 근거가 있을 때만 의도적 중복으로 판정하고, 근거가 없으면 `의도 확인 필요`로 분류한다.
- 배포 필요 자산: 유효 release가 있으면 불변 bundle을, 없으면 `dist/`와 설치 진입점을 기준으로 실제 참조 체인에 필요한 파일만 누락으로 판정하며, source 전용 운영 자산은 의도적 제외로 분류한다.
- 불필요한 제한: 실제 실패 사례나 현재 위험 모델이 확인되지 않으면 삭제를 단정하지 않고 `검증 필요` 후보로 남긴다.
- 사용자 확인: 의도·가치·완료 판단을 보호하는 확인은 유지하되, 같은 결정을 반복하거나 agent의 가역적 실행을 막는 확인은 통합·완화 후보로 분류한다.
- 외부 표준 용어: 공식 출처를 확인할 수 없으면 `외부 표준 미검증`으로 표기하고 내부 용어의 명확성만 판정한다.
