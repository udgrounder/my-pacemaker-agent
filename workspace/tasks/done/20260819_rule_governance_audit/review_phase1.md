## 검토 결과

### ✅ 정합성 확인

- 보고서의 1번 지적은 사실이다. `.mpa-workspace/core/agent_rules.md`는 minor의 완료 승인 확인을 자동화하지 않으며, `core/session_protocol.md`의 “Zone 3 — 자동 처리 후 간략 고지”와 `workspace/memory/shared/architecture.md`의 minor 예외 문구는 이를 모호하거나 상충되게 만든다.
- guidebook의 상태 흐름은 major·minor 모두 done 이동 전에 완료 승인 확인을 요구한다. 따라서 보고서가 guidebook 내부의 직접 done 이동 표현을 drift로 분류한 방향은 타당하다.
- OpenAgent의 자동 통합이 완결되지 않았다는 관찰은 근거가 있다. `install.py`는 openagent를 선택지로 받고 설치 성공을 출력하지만 진입점 추가는 건너뛰며, `agent-specs/openagent/spec.md`의 감지 조건·폴더 규칙·설치 처리는 미정이다.

### ⚠️ 주의 필요

- 보고서는 완료 승인 규칙을 설명하는 실제 hook 경로를 `hooks/code_gate.py`로 썼다. 실제 Runtime 파일은 `.mpa-workspace/hooks/code_gate.py`다. 또한 이 hook의 기본값은 `MPA_GATE=warn`이며, done 직접 쓰기는 항상 경고, `mv`만 block 모드에서 차단 가능하다. 보고서의 “요구한다”는 표현은 상태 계약으로는 맞지만 기본 집행 강도까지 강제 차단인 것처럼 읽힐 수 있어 정정이 필요하다.
- 보고서의 OpenAgent 결론은 “설치 가능한 통합 계약”의 미완결을 확인했지만, 현재 spec은 명시적으로 설치 시 실행 중인 AI agent에게 질의해 수동 설정하는 절차를 의도한다. 따라서 이를 즉시 결함으로 단정하려면 README·CLI가 ‘정식 자동 지원’으로 약속하는지와 수동 절차의 실제 실행 주체가 누구인지 분리해 판정해야 한다. 현재 증거만으로는 사용자 기대를 오도할 위험은 높지만, 설계 결함인지 미지원 기능의 명시 부족인지는 보류가 적절하다.
- “외부 도구 용어의 표준성 판정 절차가 없음”은 계획서 자체가 공식 출처를 확인할 수 없으면 ‘외부 표준 미검증’으로 표기하도록 이미 정한다. glossary에 별도 절차가 없다는 사실만으로 고위험 거버넌스 결함이나 다음 스프린트 필수 항목으로 승격한 것은 근거가 약하다.

### 🚨 즉시 수정 필요

- 완료 승인 충돌의 범위가 보고서보다 넓다. `.mpa-workspace/inject/layer1_discovery.md`는 “신규 태스크만”일 때 plan 상태를 `검토 완료`으로 둔 채 `done/` 이동하도록 지시한다. 이는 `agent_rules.md`의 `검토 완료 → 완료 승인 → done` 및 완료 승인 상태를 요구하는 hook 계약과 직접 충돌한다. 실행 단계 문서이므로 guidebook의 서술 drift보다 우선 수정·재검증해야 한다.
- `workspace/memory/shared/architecture.md`는 “.mpa-workspace 직접 수정 금지”라고 절대적으로 쓰지만, 같은 문서는 바로 뒤에서 MPA 시스템 파일 수정 절차와 동기화를 요구한다. 감사 보고서는 이를 단순한 표현 정리 후보로만 다뤘다. 실제로는 시스템 파일 수정 요청을 거부하게 만들 수 있는 라우팅 충돌이므로, 금지가 ‘비승인/설치본 직접 수정 금지’인지와 허용된 source 수정 경로를 명시해야 한다.
- 계획의 Step 6은 배포 기준본을 확정하고 설치·update·rollback 참조 체인으로 검사하도록 요구한다. 보고서는 release-audit 통과와 수량·checksum 결과를 주장하지만, 어떤 manifest/receipt의 어떤 검증 기록으로 install 경로와 rollback 시나리오를 확인했는지 증거 위치를 남기지 않았다. 재현 가능한 파일·명령·결과 링크를 보강하지 않으면 “완결성” 결론은 과도하다.

### 📝 조용한 결정 목록

- 보고서는 `agent_rules.md`를 일반 작업 흐름의 정본으로 두었지만, 같은 Runtime의 단계 inject가 이를 어길 때 어떤 문서를 우선하고 어떤 산출물을 고칠지 명시하지 않았다.
- OpenAgent를 정식 지원 선택지로 볼지, 실험적 수동 설정 경로로 볼지 결정하지 않은 채 위험으로만 분류했다.
- 외부 표준 용어의 별도 절차를 새 거버넌스 요구로 제안했으나, 계획서의 ‘미검증’ 라벨 규칙으로 충분하지 않은 이유를 제시하지 않았다.
- 기본 warn 모드의 hook을 규칙 ‘요구’의 근거로 사용하면서, 문서상 의무와 기계적 차단의 차이를 분리하지 않았다.

### 🔍 에이전트 가정 검증

- “minor 완료 확인은 자동 생략” 가정은 거짓이다. 정본 `agent_rules.md`와 상세 절차 모두 사용자 또는 위임 에이전트 확인을 요구한다.
- “guidebook의 직접 done 이동 문구만 문제” 가정은 불충분하다. 동일 충돌이 단계 실행 문서 `inject/layer1_discovery.md`에도 있다.
- “OpenAgent 선택지는 자동 연결 완료를 뜻한다” 가정은 검증되지 않았다. 구현과 spec은 수동 질의 경로를 나타낸다.
- “release-audit 통과만으로 설치·배포·rollback 계약의 종단 간 완결성을 증명한다” 가정은 검증되지 않았다. 보고서에는 해당 종단 간 증거의 위치와 재현 절차가 없다.
