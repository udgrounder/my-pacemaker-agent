# 작업 계획서: 현재 모델을 상한으로 하는 자동 서브에이전트 위임

**파생 출처:** 없음 — 사용자의 작업별 자동 위임 및 현재 창 모델 상한 요청.

**변경 이력:** [changelog.md](changelog.md) — 독립 비평 전후의 판단·보완 근거를 보존한다.

## 요구사항 명세

### 요청 기준

사용자는 에이전트가 작업 중 별도 에이전트 사용 여부와 용도별 모델을 판단해 효율적으로 처리하는 방식을 원한다. 추가로 “현재 사용하는 창의 model 보다 상위 모델은 사용하지 않고 그와 동일한 모델과 그보다 하위 모델만 활용”하도록 요청했고, 이번에는 보완 계획서 작성을 요청했다.

### 목적

메인 에이전트가 작업의 독립성·난이도·실패 비용과 전달 비용을 판단해 필요한 작업만 위임한다. 작업을 시작한 메인 창의 모델을 상한으로 유지하며, 허용된 하위 모델을 단순 작업에 활용하고 복잡한 작업과 결과 통합은 메인 모델이 책임진다.

### 범위·제외 범위

- 범위: MPA 공통 위임 지침, 모델 상한 판단 보조 도구, 설치별 모델 허용 정책 형식, Codex 호출 지침, 기존 독립 비평·검증과의 정합성, 테스트·사용자 문서·Runtime 배포본 동기화.
- 범위: 탐색·검토의 선택적 병렬 위임, 구현의 순차 위임, 호출 실패·결과 부족·모델 정보 부족에 대한 제한된 복구.
- 제외 범위: 동시 다중 구현자 운영, 새 사용자 소유 채팅 자동 생성, 외부 모델 API·별도 과금 경로, 모델 자동 설치, 사용자 전역 또는 호스트 설정 자동 변경.
- 제외 범위: 기존 inspect-only TOML 참조 계약의 실행 제어 확장, 진행 중인 TOML 작업 명세 변경, release 생성·설치 프로젝트 배포, 실제 비용·속도 개선률 보장.

### 완료 기준

1. 선택적 위임은 기존 진행 흐름/판단 맥락과 분리할 이익이 있거나 작업 자체가 독립인 경우만 후보로 삼는다. 명확한 입출력·완료 기준으로 수행·확인 가능하고 전달·검토 부담이 예상 이익을 상쇄하지 않을 때 위임한다. 독립성이 불명확하거나 작은 작업은 메인이 직접 처리한다. 상위 지침이 허용하는 범위에서 별도의 매회 사용자 확인 없이 위임할 수 있다.
2. 모든 서브에이전트·재시도·재위임에 최초 메인 창 모델의 상한이 적용된다. 목록 밖·비교 불가 모델은 명시 선택하지 않는다.
3. 모델의 상하 관계는 이름·가격·출시 순서로 추정하지 않는다. 실행 환경의 사용 가능 목록과 기준 모델별 명시 허용 목록을 교차 적용한다.
4. 현재 모델·허용 목록·실행 가능성·호스트 설정 우선순위를 확인할 수 없는 경우 상위 모델을 추정 호출하지 않는다. 상속 결과가 최초/현재 허용 집합의 교집합 안이라는 점까지 확인되면 동일 모델을 사용하고, 확인되지 않으면 선택적 위임을 생략해 메인이 처리한다.
5. 하위 모델 결과가 부족하면 현재 메인 모델까지의 제한된 복구만 허용한다. 최상한에서도 충족하지 못하면 근거·한계를 보고한다.
6. 탐색·검토는 공유 소스를 변경하지 않고, 구현은 한 시점에 한 담당자만 수정한다. 메인은 위임 결과의 근거·실제 변경·검증 결과를 확인하고 통합한다.
7. 독립 비평의 대화 미상속, 구현 검증 1차/2차 분리 및 기존 실패 처리·승인·완료 경계를 유지한다.
8. 판단 보조 도구의 입력/출력·오류·경계 테스트와 지침 로딩·정합성 검사를 통과하고 source/dist Runtime이 일치한다. 실제 호스트 호출과 보조 도구 테스트의 검증 범위를 구분한다.

### 사용자 결정

- 작업 중 에이전트가 위임 여부와 용도별 모델을 판단하는 방향으로 보완한다.
- 별도 에이전트의 이익이 있는 경우만 사용하며, 첫 판단 기준은 기존 진행 흐름/판단 맥락과의 독립성 또는 작업 자체의 독립성이다. 독립적이라는 사실만으로 무조건 위임하지 않는다.
- 현재 창의 모델과 동일하거나 그보다 하위인 모델만 사용한다. 결과가 부족하다는 이유로 상한을 올리지 않는다.
- 이번 요청은 계획 작성이다. 구현 승인·release·deploy 요청으로 해석하지 않는다.

### 변경 불가 제약

- 상한은 직전 서브에이전트 모델이 아니라 최초 메인 창 모델이다. 재위임에서 새 상한을 임의 생성하지 않는다.
- 사용 가능한 모델이라는 사실만으로 하위 모델이라고 인정하지 않는다. 다른 공급자·계열의 비교 불가 모델은 기본 제외한다.
- 사용자 승인·명세 변경·완료 판단 권한을 서브에이전트에 자동 위임하지 않는다.
- Runtime source에서 수정하고 sync-runtime으로 dist를 생성한다. 설치별 정책·계정 정보는 release asset에 넣지 않는다.
- 최초 메인 모델의 허용 집합과 현재 메인 모델의 허용 집합을 각각 동일 모델+직접 허용 하위 목록으로 구성하고, 그 교집합을 현재 유효 허용 집합으로 사용한다. 창을 더 높은 모델로 바꿔도 최초 상한을 자동 확대하지 않는다. 낮추거나 비교 불가 모델로 바꾸면 교집합 밖의 실행 중 에이전트는 중단하고 결과를 미확인으로 취급한다. 상한 변경 탐지·현재 모델 확인 불가 시 신규 명시 모델 호출을 하지 않는다.
- MPA는 호스트의 모델 선택 기능과 상위 지침을 우회하지 않는다. 판단 보조 도구를 실제 호출의 강제 차단 장치라고 표현하지 않는다.

### 정책 구조와 판단 순서

1. 상위 지침·호스트가 해당 작업의 서브에이전트 호출을 허용하는지 확인한다.
2. 기존 필수 독립 비평·검증이면 먼저 해당 절차를 적용한다. 선택적 효율 판단으로 필수 검증을 없애지 않는다.
3. 일반 작업은 아래 두 가지 독립성 중 하나를 구체적으로 확인한다. 둘 다 없거나 판단이 불명확하면 직접 처리한다. 후보인 경우 명확한 목적·입출력·완료 기준과 전달·검토 부담을 확인하고, 분리 이익이 없는 작은 작업은 직접 처리한다. 의존 결과가 준비되기 전에 에이전트를 미리 생성하지 않는다.
4. 메인 모델과 추론 수준, 가능한 호출 방식·사용 가능 모델, 사용자/프로젝트 허용 관계를 확인한다.
5. 최초 허용 집합과 현재 허용 집합의 교집합에 속하면서 실제 사용 가능하고 지원 설정까지 확인된 모델만 후보로 둔다. 동일 모델 상속도 이 집합 검사를 통과해야 한다.
6. 작은 작업은 직접 처리한다. 범위가 좁고 검증이 쉬운 탐색·정리는 하위 모델을 우선하며, 복잡 설계·위험 판단·독립 비평/검증은 동일 모델을 우선한다.
7. 호출 직전 실제 해석될 모델을 점검한다. custom agent 파일이나 [agents] 기본값이 명시 요청을 덮으면 허용 범위에 맞는 역할/호출 경로를 사용한다. 안전한 해석을 확인 못 하면 해당 호출을 생략한다.
8. 종료 후 결과의 대상·근거·판정, 구현 diff·검증 결과를 확인한다. 빈 산출물·저장 성공 문구·여러 에이전트의 동의만으로 성공 판정하지 않는다.

### 독립성 중심의 선택적 위임 기준

| 구분 | 확인 기준 | 예시 |
|---|---|---|
| 기존 진행 흐름과의 독립 | 메인이 수행 중인 작업과 별개로 진행 가능하고 수시 협의·공유 파일 수정이 필요 없음 | 메인 구현 중 다른 모듈 호출 관계를 읽기 전용 조사 |
| 기존 판단 맥락과의 독립 | 지정된 기준·산출물로 검토 가능하며, 구현 대화에서 분리하는 것이 검토 목적에 기여함 | 계획 또는 구현 결과의 독립 비평·검증 |
| 작업 자체의 독립 | 현재 대화를 대부분 전달하지 않아도 고정된 입력·완료 기준으로 끝내고 결과를 검증할 수 있음 | 특정 문서의 항목 추출, 범위가 정해진 자료 비교 |

- 독립성은 파일이 다르거나 주제가 다르다는 사실만으로 인정하지 않는다. 공유 상태·변경 중인 계약·빈번한 중간 협의·미완료 선행 결과가 필요하면 독립성이 부족하다.
- 후보가 된 작업만 최소 손익 확인을 한다. 독립 진행/검토 맥락 분리/확인된 하위 모델 활용 중 구체적인 이익을 설명할 수 있고, 전달·결과 확인·통합에 원래 작업을 대부분 다시 수행할 부담이 없을 때 위임한다. 첫 버전에는 점수표·비용 공식·정량 임계값을 도입하지 않는다.
- 호출 판단은 기존 기록에 필요할 때 한 줄로 남긴다: 독립인 이유 / 분리 이익 / 결과 확인 방법. 설명할 수 없으면 직접 처리한다.
- 기존 필수 독립 비평·검증은 해당 절차가 독립성의 목적·필요 조건을 이미 정의한다. 선택적 이익 판단으로 생략하지 않는다.
- 검증 예시: 다른 파일이지만 동일 계약 변경을 기다리는 조사와 전체 설계 설명이 필요한 작은 수정은 직접 처리; 완료된 문서를 대상으로 하는 독립 추출은 후보; 독립적이어도 한 줄 수정처럼 전달 부담이 큰 작업은 직접 처리.

### 설치별 모델 정책 및 판단 보조 도구

- 새 로컬 정책 위치: .mpa/config/agent_policy.json. Runtime 배포 범위 밖이며 없으면 생성·설치 없이 안전한 기본값을 사용한다. 실제 설정은 명시 파일 편집으로만 관리하고 전역 Codex 설정을 자동 수정하지 않는다.
- 첫 버전 정책 형식: schema_version, 호스트 식별자, 기준 모델별 allowed_lower_models, 관계의 승인 출처/근거/확인일만 제공한다. 작업별 선호·retry/concurrency 사용자 설정은 첫 버전에 추가하지 않고 공통 지침의 제한을 사용한다. 상위 모델 허용 스위치는 제공하지 않는다.
- 관계 등록 권한은 사용자 또는 사용자가 승인한 프로젝트 지침/정책에 있다. 문서의 기능 지원·실행 성공·가격만으로 새 관계를 자동 활성화하지 않는다. 이번 구현은 형식·판단 기능 제공이며 실제 로컬 허용 목록의 자동 생성/활성화는 제외한다. 승인된 관계가 없으면 하위 모델 운용은 비활성이다.
- 모델 이름을 공통 Runtime에 고정한 전역 서열표를 넣지 않는다. 문서에는 현재 환경에서 검증한 예시를 둘 수 있지만, 예시만으로 실제 허용 목록을 활성화하지 않는다.
- 새 판단 도구: .mpa/runtime/hooks/agent_policy.py. CLI는 JSON 입력/출력과 inspect/resolve에 해당하는 순수 판단만 수행하며 모델 호출·설정 생성·호스트 변경은 하지 않는다.
- 입력은 확인된 메인 모델, 가용 모델, 설치 정책, 호스트 설정 해석 결과, 호출 유형·재시도 상태·최초 상한이다. 도구는 입력의 확인 상태를 검사하되 호스트 사실을 직접 알아냈다고 주장하지 않는다.
- 입력 증거 계약: 공식 문서/도구 설명은 기능 지원 증거이고 실제 모델 식별 증거가 아니다. 메인 모델은 호스트가 노출한 현재 세션 metadata 또는 사용자가 해당 창의 모델을 명시한 정보를 사용한다. 가용 목록은 현재 도구/호스트가 제공하는 목록을 사용한다. 호출될 모델은 같은 호스트·역할의 현재 설정 우선순위를 읽어 해석한 값 또는 도구가 명시 보장한 상속 규칙으로 확인한다. 실제 모델은 반환 metadata/실행 기록이 있을 때만 확인한다. 각각 출처·확인 시점·호스트/역할을 전달하고, 세션/역할/설정 변경 시 사전 확인을 무효화한다. 이름 추정·문서 예시·요청 모델을 실제 모델로 바꿔 적은 입력은 unknown이다.
- 출력은 선택 가능 후보·선택/거부 사유·미확인 항목·직접 처리 또는 상속 권고다. malformed/중복 모델/순환 관계/자기 포함 하위 목록/알 수 없는 schema는 오류 처리하고 명시 모델 선택을 중단한다.
- 관계는 기준 모델의 직접 허용 목록만 사용한다. A가 B를, B가 C를 허용한다고 A가 C를 자동 허용하지 않는다.
- 실제 호출 도구를 가로채는 wrapper는 제공하지 않는다. 에이전트는 호출 전 판단을 사용하고 호출 결과에서 확인 가능한 실제 모델을 기록한다. 확인 자료가 없으면 요청 모델과 실제 모델을 구분해 후자를 미확인으로 남긴다.

### 작업별 실행과 실패 처리

| 작업 | 담당·모델 | 실행 조건 |
|---|---|---|
| 짧은 질문·작은 수정 | 메인 직접 | 분리 비용이 이득보다 크거나 경계 불명확 |
| 독립 탐색·정리 | 허용 하위 모델 우선 | 읽기 전용, 독립 산출물, 완료 기준 검증 가능 |
| 복잡한 설계·원인 분석 | 동일 모델 우선 | 메인이 판단을 통합하고 사용자 가치 결정을 대신하지 않음 |
| 구현 | 메인 또는 동일/허용 하위 모델의 단일 구현자 | 승인 후 순차 실행, 파일·역할 소유 범위 지정 |
| 독립 비평·검증 | 동일 모델 우선 | fork_turns=none, 단계별 지정 파일·역할만 전달 |
| 추가 분리 요청 | 메인이 현재 유효 허용 집합 안에서 생성 | 자식 직접 생성 금지; 자식은 필요성·대상만 반환하고 메인이 승인된 범위·트리 예산 판단 |

- 선택적 위임은 논리 작업 ID로 묶어 호출 오류 재시도·동일 모델 재수행을 합산 최대 1회만 복구한다. 새 자식/새 모델/새 역할로 바뀌어도 같은 논리 작업이면 예산을 초기화하지 않는다. 메인이 전체 트리의 예산을 관리하며 자식이 직접 자식을 생성하지 않는다.
- 선택적 하위 작업의 결과 부족은 근거를 전달해 1회 복구한다. 하위 모델에서 실패했으면 같은 범위의 동일 메인 모델로 재수행할 수 있으나, 같은 작업에서 재시도+상향 재수행을 별도 무한 루프로 누적하지 않는다.
- 선택적 위임의 호출 실패는 직접 처리로 전환한다. 슬롯 부족은 독립 메인 작업을 계속하거나 빈 슬롯을 기다린다.
- 필수 독립 비평·검증은 기존 _agent_execution_priority.md의 1회 재시도·격리 실패·생략 확인·자가 검증 규칙을 우선한다. 일반 위임의 직접 처리 폴백으로 이를 덮지 않는다.
- 전체 트리에서 선택적 활성 서브에이전트는 최대 2개로 제한하고 실제 남은 호스트 슬롯 중 더 작은 값을 적용한다. 필수 검증 에이전트도 호스트 슬롯 사용량에 합산한다. 필수 단계의 의존 관계는 병렬화하지 않는다.
- 구현 위임은 한 작업의 전체 구현 책임 인계만 허용한다. 파일별/하위 실행 단계별 구현 분할은 제외한다. 부모가 수정 중단·기준 diff·허용 파일·미완료 항목을 확인해 인계한 뒤 단일 구현자가 실행한다. 회수 시 자식 종료·실제 변경·남은 문제를 확인한 다음 메인이 수정을 재개한다.
- 상한/안전 상속/override 확인 불가는 필수 독립 실행 미완료로 분류하며 새로운 확인 자료 없이 재시도하지 않는다. 독립 비평은 기존 생략 확인 절차, 구현 검증은 자가 검증 및 미확인 기록으로 매핑한다. 일반 직접 처리 폴백을 독립 검증 완료로 기록하지 않는다.
- 읽기 담당자는 source·공유 memory·plan·INDEX를 수정하지 않고 지정 산출물만 작성한다. 구현 담당자는 명시된 파일만 수정하고 다른 사람의 변경을 되돌리지 않는다. 메인은 구현 담당자 실행 중 공유 파일을 수정하지 않는다.
- 기록은 위임 작업·선택 이유·요청 모델·실제 모델 확인 여부·상한·결과 근거·복구 여부를 기존 plan/changelog/review에 필요한 만큼 남긴다. 대화 전문이나 별도 상시 로그를 강제하지 않는다.

### 예상 조용한 결정

- 구현 병렬화와 하위 구현 작업 분할은 이번에 도입하지 않는다. 기존 단일 구현 책임을 유지하면서 작업 전체의 구현자를 메인에서 서브에이전트로 인계·회수하는 경우만 허용한다.
- 모델 관계는 부분 관계로 관리한다. 모든 모델을 순위로 정렬하거나 최신 모델을 자동 상위/하위로 분류하지 않는다.
- 로컬 정책 부재를 반복 질문으로 해결하지 않는다. 동일 모델의 안전한 상속 또는 메인 직접 처리로 계속하고 의미 있는 보고에 묶는다.
- 판단 보조 도구는 실제 호출 전 절차이며 강제 차단 장치가 아니다. 보장을 높이기 위한 호스트 wrapper·native hook 확장은 별도 범위다.
- 특정 모델/추론 설정을 지원하지 않는 호스트에는 안전한 축소 동작을 적용한다. 현재 창 모델을 추정해 명시 호출하지 않는다.

### 반례 (이 계획이 실패할 수 있는 시나리오)

1. 메인 모델이 노출되지 않아 이름을 추정한다 → 1·2·3단계: 명시 후보 선택 금지; 안전한 상속 확인 불가면 메인 직접 처리.
2. custom agent 설정이 요청보다 높은 모델로 덮는다 → 2·3·4단계: 해석될 설정 확인 후 허용 경로 선택; 확인 불가 경로 호출 생략.
3. 가용 목록에 있는 새 모델을 자동 하위로 인정한다 → 2·4단계: 명시 관계 없는 후보 거부; 순환/모호/알 수 없는 정책 입력도 거부.
4. 하위 모델이 재위임하며 상한을 바꾼다 → 1·2·3·4단계: 최초 상한·허용 목록 전파, 하위 실행의 권한은 확대하지 않고 메인 중심 생성.
5. 창 모델 변경 후 이전 에이전트를 계속 사용하거나 상한을 높인다 → 2·3·4단계: 최초/현재 허용 집합 교집합을 모든 호출·실행 중 대상에 적용한다. 교집합 밖 실행 중단·미확인 처리; 변경 탐지가 없는 호스트의 즉시 중단 보장은 미확인으로 보고.
6. 탐색 에이전트가 memory·INDEX까지 갱신해 구현자와 경합한다 → 1·3·4단계: 공유 파일 수정 금지·지정 독립 산출물·단일 수정자 범위 명시.
7. 하위 모델을 반복 실행해 오히려 비용이 커진다 → 1·2·4단계: 작은 작업 직접 수행, 1회 복구 총한도·동시 수 제한.
8. 호스트가 호출 전 판단을 건너뛴다 → 규칙·회귀 테스트로 경로를 명시하지만 native 강제 차단은 이번 범위에서 보장하지 않는다. 3·4·6단계의 실제 호출 근거와 운영 한계로 남긴다.
9. 상한 모델 자체의 공통 오류를 여러 동일 모델 검토가 못 찾는다 → 3·6단계: 근거·실행 결과 중심 대조, 다수결을 검증으로 취급하지 않음. 동일 모델의 상관 오류 제거를 보장하지 않는다.
