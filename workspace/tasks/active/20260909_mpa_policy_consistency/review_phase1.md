# 독립 구현 검증 1차

## 검토 범위와 방법

- `workspace/memory/shared/architecture.md`, 승인된 `plan.md`의 요구사항 명세를 먼저 읽고 실제 Runtime 문서와 대조했다. 구현 대화와 changelog.md는 읽지 않았다.
- `git diff --name-only`로 변경 목록을 확인했다. core·inject·workflows·personas·templates의 변경 파일, 활성 discovery 진입점, guidebook 관련 변경, agent-specs 4개, 현재 architecture/direction, 신규 `tests/test_policy_consistency.py`를 검토했다.
- 검토는 문서의 정책·호출 경로와 저장소 코드의 제한된 대조다. 전체 자연어 문장의 정합성이나 실제 에이전트 준수를 증명하지 않는다.
- 아래 결함은 최초 확인 및 저장 직전 재확인 시점의 파일 기준이다. 동시에 진행 중인 수정의 완료를 전제하지 않는다.

## 즉시 수정 필요

### F1 [P1] discovery 경로에서 원래 작업의 완료 승인을 건너뛴다

- 근거: `.mpa/runtime/inject/layer1_discovery.md:88`은 신규 태스크만 있으면 원래 plan을 `검토 완료`로 바꾸고 INDEX 제거 및 done 이동을 지시한다. 같은 파일 `:126`은 `검토 완료` 상태와 done 이동을 종료 조건으로 재확인한다.
- 재현 경로: 결과 검토 후 신규 기능만 발견 → discovery 3단계 신규 태스크 등록 → 4단계에서 원래 태스크 자동 종료. 원래 결과에 대한 명시적 완료 확인이 없더라도 이 경로가 실행된다.
- 위반: 명세의 기존 완료 승인 보존 및 최신 core의 `완료 승인` 뒤 done 이동 규칙. guidebook의 수정된 흐름은 사용자 완료 승인 뒤 종료하도록 설명하므로 설명과 실제 단계 지침도 다르다.
- 권장: 신규 항목 등록과 원래 결과의 완료 승인을 분리한다. 승인 전 원래 작업을 유지하고, 유효한 완료 확인 뒤 `완료 승인` 전환 및 done 이동을 처리하도록 표와 종료 체크를 함께 수정한다. 기존 완료 확인은 재사용한다.

## 주의 필요

### F2 [P2] 직전 승인 기록 복구가 동일한 승인을 다시 요구한다

- 근거: `.mpa/runtime/core/agent_rules_detail.md:48`의 `직전 승인 후 기록만 누락` 분기가 사용자에게 다시 보여주고 확인한 뒤 approve하도록 요구한다.
- 재현 경로: 사용자가 현재 명세의 구현을 명시적으로 승인했으나 해시 기록만 누락 → hook의 승인 기록 복구 경고 → detail의 분기에서 사용자에게 같은 확인 재요청.
- 위반: 명세 완료 기준 8·9와 core의 유효한 동일 범위·위험 승인 재사용. 사용자 승인 사실·대상이 분명하고 명세/위험도 동일한 경우에도 재확인이 필수로 남는다.
- 권장: 현재 명세·위험과 직전 명시 승인 근거를 대조할 수 있으면 에이전트가 기록을 복구하고 결과를 보고한다. 승인 근거·대상 동일성이 불명확하거나 명세·위험이 달라진 경우에만 확인한다. 임의 승인 생성은 허용하지 않는다.

## 제한된 확인 결과

- minor 직접 구현 진입은 `layer1_implement.md:124`에서 detail 정본을 읽고, 최소 확인·증거 또는 미확인 이유를 기록한 뒤 완료 확인을 기다린다. 문구/설정/동작별 확인 및 외부 동작 변경 시 중단·재판정·재개/승격 기준이 detail 291–303행에 존재한다. 직접 진입에서 최소 확인을 전혀 수행하지 않고 완료하도록 지시하는 경로는 이번 검토에서 추가 발견하지 못했다.
- 독립 실행 정본은 대화 상속 없음·유효 산출물 확인을 요구한다. 도구 없음/격리 불가/호출·산출물 실패를 미완료로 분류하고, 비평의 생략 사용자 판단과 구현 검증의 한계를 기록한 자가 검증을 구분한다. 사용자 소유 새 작업 생성으로 대체하지 않는 규칙도 있다.
- gate 설명은 기본 warn, 선택 critical 예외, off/block, 미상 도구/경로 및 Bash 감시 한계, 해시가 사용자 인증을 보장하지 않음을 구분한다. spec의 실제 호스트 확인은 미확인으로 남아 있다.
- `python3 -m unittest discover -s tests -p test_policy_consistency.py -q`: 8 tests, OK. 참조 누락/금지 문자열 및 실제 gate 스크립트의 제한된 입출력 확인이며 의미 정합성 증명은 아니다. F1/F2가 남아 있어도 이 검사가 통과하므로 관련 회귀 사례를 보완할 필요가 있다.
- `diff -qr .mpa/runtime dist/.mpa/runtime`: 출력 없음, exit 0. 대조 시점의 Runtime parity를 확인했다.
