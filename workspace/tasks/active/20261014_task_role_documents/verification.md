# 검증 문서: 역할별 작업 문서 도입

**상위 기준:** [plan.md](plan.md)의 요구사항 명세/완료 기준.
**기준 상태:** 승인된 plan 명세 reqspec-v1:379e670bdd19a370에 연결됨. 실제 판정은 실행 증거와 대조한다.
**담당:** 독립 검증 담당. 실제 결과는 단계별 review 파일에 저장한다.
**사용 이유:** 단일/선택 역할 문서·승인 호환·입력 격리의 검사 방법을 구현 진행 설명 없이 전달한다.
**1차 입력:** plan 프론트매터의 승인/상태/문서구성, 요구사항·관련 핵심 결정·선택 문서 목록, 검토된 implementation.md의 설계 기준 섹션, 이 문서의 검증 기준, 필요한 공통 memory와 실제 변경 소스.
**1차 배제:** plan 진행 요약/완료 주장, implementation 진행 기록/완료 주장, changelog, 구현 대화, 2차 결과.
**2차 입력:** plan 승인/요구사항/선택 문서, 1차 결과, implementation 실행/진행 기록, changelog, 필요한 실제 소스. 구현자 주장은 대조 대상으로만 사용한다.
**실행 전 확인:** 문서 전환 점검과 Runtime 제품 검증을 구분하며, 승인·선택 입력 연결을 확인하고 미승인 Runtime 구현을 완료로 판정하지 않는다.
**변경 권한:** 검증 결과 작성. 명세/검증 기준 축소·구현 수정은 메인에 반환한다.

## 검증 기준

### 검증 체크리스트

- [ ] 정상: major/minor 모두 최소 plan 유지; major의 plan 단독, implementation만/verification만/ui_design만 추가, 필요한 조합을 지원; 단계별 입력·같은 명세 기준·문서 타입별 실행 판단.
- [ ] 화면 설계: implementation의 소프트웨어 설계와 ui_design의 화면 설계의 생성 조건/입력/담당 구분, 디자인 원본 연결, 로딩/빈 화면/오류 등 상태, 구현과 실제 화면의 기준 대응·시각 검증. UI 없는 작업에는 화면 문서 생성하지 않음.
- [ ] 실패: 선택된 역할 문서 누락·unknown 구성·기준 오래됨·명세 복구 중단·하위 문서 저장 실패·완료 기준 축소. 선택하지 않은 역할 문서 부재는 정상.
- [ ] 호환: minor 단일·표식 없는 기존 plan·legacy 해시·reqspec 명세 외 이동·plan/changelog 복구·INDEX 단계 정본 유지.
- [ ] 격리: 1차 프롬프트와 실제 읽기에 구현 완료 설명/changelog가 없음; 2차에서 단계 이행 대조.
- [ ] 활용: 범위가 고정된 fixture에서 구현/검증 담당이 불필요한 이력 없이 작업·판정을 수행할 수 있음. verification 문서에 따른 검증 한 건을 해당 역할 문서+필요 plan 기준→최소 입력의 동일 모델 미상속 에이전트 전달→기존 review 산출물 수령→메인 근거 확인으로 수행하고, 기본 역할 문서로 선행 조건·담당 범위·상위 요구사항 연결을 이해했는지 확인. 별도 자료 관리가 필요한 큰 작업/조사 사례는 하위 폴더·최소 작업 문서의 선택 생성과 상위 연결을 추가 확인한다. 호스트 호출 불가 시 문서 형식 테스트와 실제 인계 미확인을 구분하며 활용 완료를 주장하지 않음. 문서 수 감소/속도 개선률은 주장하지 않음.
- [ ] 갱신/복구: 같은 명세에서 검증 기준 축소·implementation의 설계 기준 변경은 대응 확인 무효화; 진행 체크 변경은 유지. 최초 approve 직후/첫 하위 연결 저장 후 중단·재개 성공과 renew-spec 중단·복구를 각각 검증.
- [ ] 입력 격리: split/단일형의 진행 기록에 식별 문구를 넣고 1차 실제 읽기/diff에는 없으며 2차에는 필요한 대조 기록이 있는지 확인. 선택된 ui_design 누락·오래된 기준과 단일형 역할 입력도 검사.
- [ ] 정합성: inspect-only 계약 미확장, 기존 critical/일반 hook 강도 유지, source/dist 동치, 현재 최초 적용 작업 외 기존 task 무변경.

### 예정 검증과 증빙

- python3 -m unittest discover -s tests -p 'test_task_documents.py' — 문서 구성·필수 경로·기준 연결·임시 전환.
- 같은 방식으로 test_plan_hash.py, test_structure_loading.py, test_todo_policy.py, test_policy_consistency.py, test_contract_reference.py — 영향 경로 회귀.
- python3 release_manager.py sync-runtime — 구현 뒤에만 실행; source/dist 일치 검사 포함. release/deploy 미실행.
- 임시 fixture의 전달 입력·독립 담당 결과·누락/불일치 판정을 증빙으로 저장하고 확인 불가 항목은 미확인으로 기록.

- [ ] 분리 관리: 작은 작업에 별도 지시서/폴더를 강제하지 않음; 큰 독립 작업/조사에서는 생성 필요성·상위 등록·자료/결과 경로·권한 불확대·입력 누락 처리를 확인.

### 요구사항 대응

| plan 완료 기준 | 확인할 증거 |
|---|---|
| 1~3 | 현재 문서 분리 사례 및 major plan 단독/선택 조합 fixture, 중복 정본 없음 |
| 4 | 기본 역할 문서 직접 전달, 필요 시 큰 작업/조사의 별도 문서·폴더, 상위 기준·입출력·담당·의존성 연결 |
| 5 | 기존 승인·해시·plan/changelog 복구 회귀 |
| 6 | 1차 기준 섹션 입력과 주장 배제, 2차 실행 기록 대조 |
| 7~8 | 선택 문서 누락/기준 변경/전환 실패 검사, source/dist 동치 |
| 9 | 구현/검증 인계에서 추가 질문·누락 제약·불필요한 읽기·수동 정리 확인 |

현재 작업에서 먼저 확인할 사항은 plan의 최소 정본, 선택 문서 연결, 문서 간 내용 소유·중복, 역할 담당의 입력 충분성이다. 이 문서 전환의 성공을 Runtime 구현·효율 개선 입증으로 판정하지 않는다.

## 결과 저장과 완료 판정

- 1차: review_phase1.md에 요구사항별 근거·판정·미확인 항목.
- 2차: review_phase2.md/review_summary.md에 구현 기록과 1차 판정 대조.
- 메인이 증거를 확인하고 plan에 전체 상태만 반영한다. 파일 존재/저장 성공만으로 합격 처리하지 않는다.
