# 태스크 계획서: 태스크 INDEX 메모리 정리 정책

## PRD

### 에이전트 보고

#### 사용자 결정 필요 (Open Questions)

- 없음

#### 암묵적 결정

- `workspace/tasks/INDEX.md`는 모든 MPA 사용 프로젝트에서 최근 태스크를 빠르게 찾기 위한 참조용 메모리다. `workspace/tasks/done/`은 완료 태스크의 이력 원본으로 유지한다.
- 정책은 설치 대상 프로젝트에 전파하며, MPA를 사용하는 현재 프로젝트의 INDEX에도 같은 형식과 유지보수를 적용한다.
- INDEX에서 제거하는 것은 만료된 done 행뿐이며, 태스크 폴더·plan.md·Layer 2 완료 마커는 삭제하거나 이동하지 않는다.
- INDEX에 없는 done 폴더는 정리된 캐시 항목으로 보고 자동 복구하지 않는다. 만료된 done 행은 이후 Layer 2 제안 집계에서도 제외한다.

#### 에이전트 가정 (Assumptions)

| 가정 | 근거 | 틀렸다면 |
|-----|------|---------|
| 보존 기간은 프로젝트 실행 시점의 현지 날짜 기준 달력 3개월이다. 완료일이 정확히 3개월 전이면 정리 대상이다. | 사용자가 “완료일로부터 3개월 이상”이라고 지정했다. | 일수 또는 UTC 기준으로 바꾼다. |
| INDEX 정렬은 `active` → `hold` → `done` 순이다. 각 그룹은 active/hold는 생성일, done은 완료일 내림차순이며 같은 날짜에는 태스크명 오름차순이다. | 진행 중인 태스크와 최근 완료 이력을 먼저 참조하게 한다. | 원하는 정렬 기준으로 교체한다. |
| 날짜 형식이 비어 있거나 `YYYY-MM-DD`가 아닌 행은 자동 삭제하지 않고 보존·경고한다. | 캐시 유지보수가 태스크 이력을 조용히 잃게 해서는 안 된다. | 오류 행을 차단 또는 별도 복구 절차로 바꾼다. |

### 요청 원문

> MPA 정책을 수정. task 진행 시 참조 혹은 작성하는 INDEX.md 정책을 수정할 것이다. INDEX.md가 참조용 메모리인데 메모리 정리를 하지 않는다. 오래된(완료일로 부터 3개월 이상된 완료된 작업) 거 정리랑, INDEX 내 task간 정렬을 해야 한다. 현재 완료일이 없는 건 현재 시간을 기준으로 처리해줘.

### 목적

태스크 INDEX가 진행 중인 태스크와 최근 완료 태스크만 담는 정렬된 참조 메모리로 유지되게 한다.

### 요구사항

- INDEX 표에 `완료일` 열을 추가한다.
- 완료 처리 시 done 행의 완료일을 기록한다.
- 완료일이 없는 기존 done 행은 정책을 적용하는 시점의 현재 날짜로 채운다.
- 완료일 기준 3개월 이상 지난 done 행은 INDEX에서 제거한다.
- INDEX를 참조하거나 작성하는 태스크 흐름에서 정리와 정렬을 수행한다.
- 한 번의 유지보수는 기준일을 한 번만 계산하고, 상태·완료일 반영 → 기존 완료일 보정 → 만료 done 행 제거 → 태스크 행 정렬 → 마커 보존 순으로 INDEX를 한 번만 저장한다.
- 현재 프로젝트와 신규 설치 템플릿·설치본 규칙이 같은 정책을 사용한다.

## 구현 계획 (Implementation Plan)

### 사전 조사

- INDEX를 읽는 세션 시작·Layer 2와, INDEX를 쓰는 태스크 생성·major 완료·minor 완료 흐름을 확인한다.
- 완료일이 없는 현재 INDEX의 done 행은 이 태스크를 구현하는 시점의 현재 날짜로 보정한다.

### 구현 단계

- [ ] Step 1 — 현재 `workspace/tasks/INDEX.md`에 `완료일` 열을 추가한다. 기존 done 행의 완료일은 구현 시점의 현재 날짜로 채우고, active/hold 행은 `-`로 둔 뒤 정책 순서로 정렬한다. / 이유: 현재 프로젝트도 MPA 사용 프로젝트로서 새 정책의 기준 형식을 바로 사용하게 한다.
- [ ] Step 2 — `agent_rules.md`에 INDEX 유지보수 정책을 추가한다. 세션 시작에서 INDEX를 참조하기 전, 그리고 태스크 생성·완료에서 행을 갱신한 뒤 공통 유지보수를 수행하게 한다. 한 번의 처리에서는 기준일을 한 번 계산하고 `상태·완료일 반영 → 기존 완료일 보정 → 만료 done 행 제거 → 태스크 행 정렬 → 마커 보존 → 한 번 저장` 순서를 지킨다. / 이유: 완료 행이 잘못된 위치에 남거나 중간 상태가 저장되는 것을 막는다.
- [ ] Step 3 — major·minor·구현 후 발견으로 생기는 태스크 생성과 major·minor 완료 지점을 새 표 형식에 맞춘다. 생성 시 `완료일: -`를 기록하고, 완료 승인 후 상태를 done과 실제 완료일로 갱신한 다음 공통 유지보수를 수행한다. / 이유: 이후 보존 기간과 정렬에 필요한 값이 누락되지 않게 한다.
- [ ] Step 4 — `layer2_checkpoint.md`의 INDEX 동기화·집계 규칙을 갱신한다. active/hold 폴더만 INDEX 누락을 복구하고, INDEX에 없는 done 폴더는 만료 정리된 정상 이력으로 간주한다. Layer 2 제안은 INDEX에 남아 있는 done 행만 집계하며, `[Layer 2 완료]` 마커는 태스크 행 정렬 대상에서 제외한다. / 이유: 정리된 done 행의 재등록·오래된 이력에 따른 반복 제안·점검 마커 훼손을 막는다.
- [ ] Step 5 — 신규 설치 템플릿 `dist/workspace/tasks/INDEX.md`에 새 열과 정책 설명을 반영한다. 기존 설치본은 업그레이드 후 첫 세션에서 보존된 INDEX를 보정하고, 이미 보정된 INDEX는 재실행해도 완료일이 변하지 않도록 규칙을 명시한다. / 이유: 신규 설치·업그레이드·재실행이 같은 결과를 낸다.
- [ ] Step 6 — 현재 INDEX와 날짜 경계 예시를 사용해 완료일 보정·3개월 만료 제거·정렬·Layer 2 done 미재등록 규칙을 검증한다. 날짜가 잘못된 행은 보존·경고되는지도 확인한다. 이어서 설치본 `.mpa-version`의 `current_version`을 갱신하고 `dist_sync.py`를 실행해 설치본과 dist의 차이가 없는지 확인한다. / 이유: 실제 참조 메모리 유지보수·배포 흐름이 모순 없이 동작함을 검증한다.

### 예상 조용한 결정

- 완료일 보정과 만료 정리는 INDEX를 처음 참조하거나 작성하는 시점에 한 번의 유지보수 순서로 수행한다. 같은 실행에서 기준일을 고정하고 INDEX 전체를 한 번만 저장한다. / 권장: 날짜 보정 뒤 즉시 만료를 판단해 재실행해도 결과가 유지되게 한다.
- INDEX 하단의 `[Layer 2 완료]` 행은 태스크 표와 분리된 상태 마커로 유지한다. / 권장: 태스크 행만 정렬한다.
- INDEX에 없는 done 폴더는 자동 등록하지 않고, Layer 2 제안은 보존 기간 내 INDEX done 행만 사용한다. / 권장: INDEX를 최근 태스크용 캐시로 일관되게 유지한다.

## 완료 기준 (Definition of Done)

### 검증 체크리스트

- [ ] 현재 INDEX의 모든 done 행이 완료일을 가지며, active/hold 행은 `-`인지 확인한다.
- [ ] 완료일이 정확히 3개월 전인 done 행은 제거되고 해당 done 폴더는 유지되는지 확인한다.
- [ ] active → hold → done 순서 및 날짜·태스크명 보조 정렬이 적용되는지 확인한다.
- [ ] major·minor 완료 절차 모두 완료일을 기록하도록 명시됐는지 확인한다.
- [ ] Layer 2 규칙이 누락된 done 행을 재등록하지 않고, 보존된 done 행만 집계하며, 마커를 보존하는지 확인한다.
- [ ] 잘못된 완료일 행을 자동 삭제하지 않고 경고하도록 명시됐는지 확인한다.
- [ ] 신규 설치·기존 설치본의 첫 세션·같은 INDEX 재실행에서 각각 기대한 보정과 멱등 결과가 나오는지 확인한다.
- [ ] dist의 MPA 규칙과 태스크 INDEX 템플릿이 설치본과 일치하는지 확인한다.
